# ToolHazard: Scaling Adversarial Environments for Security Evaluation and Alignment of LLM-based Agents

- **Paper:** [arXiv:2608.11878](https://arxiv.org/abs/2608.11878)
- **Authors:** Yutao Mou, Pengfei Yang, Zhe Yin, Zhangchi Xue, Xiaotian Luan, Dingyao Yu, Tong Zhang, Shikun Zhang, Wei Ye
- **Institution:** Peking University (Wei Ye's group, per prior publications)
- **Published:** 2026-08-12 (v1)
- **Subjects:** cs.CR, cs.CL
- **Code:** Not listed on the arXiv page.

## Problem Statement (plain English)

LLM agents that call external tools are vulnerable to indirect prompt injections hidden in the environment (web pages, files, API responses). But security researchers can't scale their testing: today's benchmarks are built by hand or reuse the same few environments, simulate tools with stochastic LLM calls (not real executable state), and place injections at predefined spots. Testing an agent across many real-world domains and attack styles is therefore slow and expensive, and the resulting data can't easily be turned into training/alignment data to make agents safer.

## Methodology (technical)

ToolHazard is a synthesis framework with three components:

- **Environment Simulator** — builds *executable, stateful* environments (not stochastic LLM stand-ins), so agent actions have real consequences the evaluation can verify.
- **Attacker Agent** — explores each environment, discovers viable injection points automatically, and generates environment-specific attack payloads (instead of researchers hand-placing injections).
- **User Simulator** — constructs state-grounded, long-horizon tasks for the victim agent to perform inside the adversarial environment.

The pipeline is scalable: adding seed domains and compute expands coverage without new manual engineering. It produces **ToolHazard-Bench** (stress-testing agents under complex workflows and diverse environmental attacks) and, separately, alignment data derived from the attacks.

## Key Results (with numbers)

- ToolHazard-Bench exposes substantial agent vulnerabilities across complex workflows and diverse attack types.
- Injection **timing and placement** materially affect attack effectiveness — a variable most benchmarks collapse.
- Fine-tuning on ToolHazard-generated alignment data improves security on **both ToolHazard-Bench and AgentDojo** (an established benchmark) while preserving benign task utility — i.e., the synthetic environments transfer to real robustness gains.

## What's Novel

- Replaces hand-built/reused environments with **compute-scalable synthesis**: add seed domains and compute, get more adversarial environments — no per-domain human engineering.
- Executable stateful environments (vs. stochastic LLM tool simulation), enabling verifiable, reproducible attack evaluation.
- Closes the loop between red-teaming and alignment: the same pipeline that finds attacks generates data that measurably hardens agents (cross-benchmark transfer, utility preserved).

## My Connection (to Manny's work)

This is the "scale red-team environments like you scale training data" blueprint. Manny's agent-evaluation tooling should be heading toward synthesis (attacker agent finds injection points, user simulator builds tasks, executable envs for verifiable outcomes) instead of hand-curated harnesses — and the alignment-data payoff means security eval output can be productized, not just reported.

## What I Learned (plain English)

Two things. First, injection *placement* matters as much as payload quality — where in a workflow the poisoned content appears changes whether the agent bites, so benchmarks that fix injection locations overstate agent safety. Second, synthetic adversarial environments aren't just for measurement: attacks generated by an attacker-agent pipeline can be converted into training data that makes agents measurably safer on *other* benchmarks too. That's the strongest argument yet for building red-team infrastructure that produces both findings and fixes.
