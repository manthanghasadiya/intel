# When Feedback Becomes a Backdoor: Tracing Backdoor Skill Formation in Text-Space Skill Optimization

## Problem Statement

"Text-space skill optimization" is the loop where an agent reflects on its own performance and writes reusable instructions — a Skill — for future runs, using reference answers as supervision. Everyone has been worried about *downloading* a poisoned skill. This paper asks whether a skill can be poisoned *as it is being born*: if the reference answers used during optimization are attacker-influenced, can a trigger-conditioned rule end up in the final skill without the attacker ever touching the model weights, the optimizer, or the skill file?

## Methodology

They instrument **SkillOpt** (a text-space skill optimization loop) and trace an attacker-supplied **trigger → payload mapping** through four stages:

1. **Reflection** — the agent reasons over reference feedback.
2. **Rule formation** — a candidate rule appears in the reflection output.
3. **Selection** — the rule survives the optimizer's editing/ranking of the skill text.
4. **Held-out activation** — the rule fires, or doesn't, at inference time.

Two tasks: **SearchQA**, where the payload is a short answer substitution, and **SpreadsheetBench**, where the payload requires an additional workbook edit. Three seeds per task, plus diagnostic interventions that disable individual stages to find the bottleneck.

## Key Results

- **SearchQA:** the natural attack retains an exact rule in **all three seeds**. The final skill emits the payload on **200/200 triggered questions and 0/200 clean questions** — perfect separation, with no degradation in clean accuracy (169/200 poisoned vs 171/200 benign).
- **Causal confirmation:** in seed 42, removing the rule eliminates the activation entirely — the rule *is* the backdoor.
- **SpreadsheetBench:** no natural run retained an exact rule across three seeds. Exposure alone isn't enough when the payload needs more than a literal substitution.
- **Two bottlenecks identified:** (a) the *Analyst* stage abstracts away the required literals; (b) once literal preservation is forced, edit-budget ranking can silently drop the exact edit before candidate construction.

## What's Novel

The supply-chain model is inverted. Prior skill-poisoning work assumes an attacker ships a malicious Markdown file; this shows the attacker only needs to influence *feedback*, and the optimizer will manufacture the backdoor itself — complete with a plausible-looking rationale. The stage-by-stage trace turns "can it happen" into "which stage to harden," which is far more actionable.

## My Connection

Manny runs agents that write their own skills/memory from experience. This is the concrete failure mode of that loop: the artifact looks legitimate, passes review (it's a synthesized instruction, not a suspicious payload), and only fires on a trigger. Any self-improving loop that ingests external reference answers is in scope — and the diagnosis is that preserving exact literals in reflection output is the thing that makes the attack *work*, so that's also the choke point to control.

## What I Learned

Self-improvement is an attack surface with a paper trail. An agent that learns from feedback can be taught a secret rule by whoever controls a fraction of that feedback — and because the rule is generated by the agent itself, it inherits the agent's voice and its trust. The defense isn't better scanning of skill files; it's provenance on the reference answers and a hard rule that no literal from untrusted input survives into a reusable artifact without being flagged.
