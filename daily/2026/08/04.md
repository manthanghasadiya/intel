### [📄 TP-Link Omada ZTP: 15 Vulnerabilities Chain Into Full Network Takeover](https://www.securityweek.com/tp-link-omada-ztp-vulnerabilities-chain-into-full-network-takeover/)
**⏱ Read time:** 5 min

Forescout disclosed 15 vulnerabilities in TP-Link's Omada zero-touch provisioning (ZTP) ecosystem, including hardcoded cryptographic keys, insecure credential transmission, weak certificate validation enabling MITM, a cloud adoption race condition, and predictable device serial numbers. Eleven were assigned CVEs (TP-Link declined four). Combined with two previously known RCE flaws (CVE-2025-7850/7851), an external attacker with no network access can exploit the cloud race condition to intercept credentials and gain administrative control of a cloud controller account. Forescout found 1,800 Omada controllers exposed to the internet. The same weaknesses extend to TP-Link's VIGI, Festa, Tapo, and Kasa lines. Patches are partial — structural fixes may not complete until late 2026. Disclosure at Black Hat Wednesday.

**Why it matters:** Consumer-grade networking gear managing enterprise fleets via cloud ZTP is a persistent supply chain risk — the Tapo/Kasa smart home overlap means compromises can pivot from home networks into corporate environments.

### [📄 22-Year-Old BMC Vulnerability Exposes 24,000+ Data Center Management Interfaces](https://www.securityweek.com/decades-old-bmc-vulnerability-exposes-thousands-of-data-centers-to-attacks/)
**⏱ Read time:** 4 min

Data center security firm Lava reports that CVE-2013-4786, a flaw in the IPMI 2.0 authentication protocol introduced in 2004, remains actively exploitable. The vulnerability lets unauthenticated remote parties obtain HMAC-SHA1 password hashes from BMC responses on UDP port 623 and crack them offline. Lava found 37,000 internet-exposed IPMI interfaces, with 24,000+ leaking authentication hashes before login. 6,240 hosts accepted empty usernames with weak passwords; 2,340 used common passwords from public wordlists. Since the same user database serves IPMI, the web interface, and the Redfish API, cracking one yields full server management access — power cycling, firmware updates, and low-level configuration changes.

**Why it matters:** Baseboard management controllers are the most privileged control points in data centers — a single exposed BMC with a weak password becomes a silent root foothold across the entire management network, and offline cracking means no login attempt logs to detect.

## 🔌 MCP / AI AGENTS

### [📄 Gemini ADK Agent-to-Agent Attack: Public Agent Bridges to Privileged Agent via Prompt Injection](https://www.securityweek.com/gemini-agent-to-agent-attack-exposed-secrets-enabled-pull-request-tampering/)
**⏱ Read time:** 6 min

Pillar Security discovered an agent-to-agent attack in Google's Agent Development Kit (ADK) Python repository. The repo ran two classes of automated AI agents: low-privileged triage agents open to public interaction, and high-privileged code-fixing agents restricted to maintainers. An attacker could prompt-inject the public triage agent into posting `/adk-issue-fix` as the `adk-bot` account (a Collaborator), which satisfied the privileged workflow's owner/member/collaborator gate. The trusted bot identity became the authorization bridge — the gate checked who posted the command, not whether an outsider manipulated the trusted account behind it. Pillar demonstrated RCE on the CI runner, exfiltration of the bot's PAT, and access to a Google API key and Cloud service-account credential. The agent could write payload files via `CapabilitiesConfig()` and execute them through Git hooks despite a `gh`/`git` command allowlist. Google deleted 3 ADK workflows, fixed the issue through hardening in late July, but did not issue a bug bounty (social engineering required for full PR merge). A second vulnerability enabled RCE without maintainer interaction.

**Why it matters:** This is the canonical agent privilege escalation pattern — a low-trust agent trusted by a high-trust workflow becomes a bridge for any unauthenticated attacker. Every repo using AI agent automation needs to audit bot identity isolation, token scope separation, and whether untrusted text can trigger privileged workflows.

**Why it matters:** MCP server inventory + runtime agent governance is becoming a recognized category — the 13% real-time enforcement stat means 87% of enterprises have zero visibility into what their agents are connecting to or executing.

## 🔥 HOT TAKE + CONTENT IDEA

The Gemini ADK attack and the AutoBypass paper together tell the story: AI agents are now both the target and the weapon. The ADK attack shows that agent-to-agent privilege escalation is trivial when a trusted bot identity becomes an authorization bridge — no exploit needed, just prompt injection. AutoBypass shows that multi-agent orchestration can autonomously generate working EDR evasion payloads at 90% bypass rates. For content: write a technical breakdown of the agent trust boundary model — when does one agent's output authorize action for another agent? The answer right now: almost always, and that's the problem.
