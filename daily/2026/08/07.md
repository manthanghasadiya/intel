## 🔐 SECURITY

### [📄 AI-Assisted HTTP Terminator Finds Novel HTTP Desync Techniques and Apache Zero-Day](https://thehackernews.com/2026/08/ai-assisted-http-terminator-finds-novel.html)
**⏱ Read time:** 3 min

PortSwigger's James Kettle open-sourced HTTP Terminator, an AI-assisted research system that ingested 138 HTTP/SMTP RFCs (~15,000 fragments) and generated 30,000 candidate desync vectors, finding ~700 vulnerable targets across bug-bounty-authorized sites — banks, government infrastructure, an airport. It produced new desync triggers, a dual-matching Content-Length pattern, and a "dangling-byte" technique that makes response queue poisoning reliable. A human-guided cascade also found an Apache Traffic Server zero-day (CVE-2026-63078, patched but not yet verifiable in public records). Kettle: "Neither of us would have discovered it alone."

**Why it matters:** The first clear proof that AI can autonomously generate novel web-attack techniques at scale — red-team automation is no longer theoretical, and Manny should be testing agents against his own infra.

### [📄 New NatJack Attacks Hijack TCP Sessions and Spoof DNS by Manipulating NAT Tables](https://thehackernews.com/2026/08/new-natjack-attacks-hijack-tcp-sessions.html)
**⏱ Read time:** 2 min

Black Hat USA 2026 research (Malcolm Stagg, SODIUM-24) discloses NatJack: an attacker with privileged access behind the same NAT can manipulate connection-tracking state to hijack active TCP sessions, spoof DNS responses, expose mapped ports, and exhaust NAT tables. Two CVEs: CVE-2026-56181 (Windows NAT/Hyper-V, 8.3) and CVE-2026-63913 (Linux Netfilter conntrack, 8.2). No single patch for the class — fixes only raise complexity; mitigation is separating untrusted workloads from shared NAT infrastructure.

**Why it matters:** The same-NAT trust assumption is pervasive in cloud and container networking — including the multi-tenant environments where Manny's agents run.

### [📄 Malware Can Abuse Windows Hello for Business Keys for Persistent Entra ID Access](https://thehackernews.com/2026/08/malware-can-abuse-windows-hello-for.html)
**⏱ Read time:** 2 min

Dirk-jan Mollema shows malware in a signed-in session can silently use the victim's Windows Hello for Business key (TPM-backed, no PIN/biometric needed, no admin required) as a FIDO2 passkey via WebAuthn to get Entra ID assertions — then register a rogue device, grab a 90-day Primary Refresh Token, and add auth methods. **Why it matters:** Phishing-resistant MFA has a session-level bypass — credential material stays hardware-bound while malware inside the session invokes it for the attacker.

## 🔌 MCP / AI AGENTS

### [📄 Claude Code and Gemini CLI Flaws Let a GitHub Issue Reach CI Workflow Secrets](https://thehackernews.com/2026/08/claude-code-and-gemini-cli-flaws-let.html)
**⏱ Read time:** 3 min

Novee Security (Black Hat USA, Aug 5) hit Anthropic's, Google's, and OpenAI's own coding-agent repos with unauthenticated GitHub issues that executed code on their CI runners. Gemini CLI's container launcher had CVE-2026-12537 (CVSS v4 10.0) OS command injection via a crafted `.gemini/.env`; Claude Code's CVE-2026-54316 turned Hugging Face's public download counter into a one-character-at-a-time API key exfiltration channel (affected 0.2.54→2.1.163); the Codex finding got no CVE at all — OpenAI's sandbox "behaved as documented," so the fix was workflow-level (separate jobs, read-only sandbox, AGENTS.md now treated as untrusted input). Novee's take: "The harness is the code between the model and the real world."

**Why it matters:** Three vendors' own agent pipelines fell to instruction-file and validator-trust bugs — the exact harness layer Manny audits, now proven exploitable from a zero-privilege GitHub issue.

**📄 Related paper:** [The Vulnerability With No CVE: Agentic Posture Vulnerabilities in AI Coding Agents](../../papers/2026/08/agentic-posture-vulnerability.md) — the Codex outcome (no CVE, no patch) is precisely the gap this paper formalizes.

### [📄 Hardware Keystores for AI Agent Signing Workflows: A Zero-Trust MCP Enforcement Architecture](https://arxiv.org/abs/2608.06130)
**⏱ Read time:** 3 min
**📄 Full breakdown:** [papers/2026/08/zero-trust-mcp-hardware-keystores.md](../../papers/2026/08/zero-trust-mcp-hardware-keystores.md)

New paper (Sambrook & Sovio, Aug 6) moves agent signing keys out of software into hardware keystores (HSM/TPM/smart card) behind a vendor-neutral PKCS#11 interface, wrapped in a five-layer zero-trust stack (session identity, scope bounds, semantic validation, taint tracking, hardware boundary). Against AgentDojo's ImportantInstructionsAttack (12 injection scenarios, 4 LLMs), baseline ASR of 19.3% dropped to 0% (upper bound 2.0%) when protected — motivated by a real incident where agent keys were exfiltrated via email injection in under five minutes.

**Why it matters:** Directly addresses MCP signing workflows — hardware-confined keys plus content-aware authorization close the prompt-injection→key-exfiltration class entirely.
