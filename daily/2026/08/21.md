## 🤖 AI NEWS

### [📄 Ramp launches its own AI model router, called Router](https://techcrunch.com/2026/08/20/ramp-launches-its-own-ai-model-router-called-router/)
**⏱ Read time:** 2 min

Ramp launched Router, an LLM routing API letting customers switch between models from OpenAI, Anthropic, DeepSeek, Moonshot, Minimax, Nvidia, xAI, and Z.ai, with routing "strategies" (flex-tier preference, benchmark-based routing, cheap-for-easy/expensive-for-hard). Free through 2026, with a $26 credit; Ramp says it has dogfooded it internally for three years. It's a direct OpenRouter-style play from a fintech, hot on the heels of Stripe's OpenRouter acquisition.

**Why it matters:** Every company with AI spend is becoming an inference gateway — routing layers are a new trust boundary (credentials, retention opt-outs, prompt data) that security teams will need to audit.

## 🔐 SECURITY

### [📄 Microsoft Entra ID Flaw (CVSS 10.0) Exploited in Wild, Allows Remote Code Execution](https://thehackernews.com/2026/08/microsoft-entra-id-flaw-cvss-100.html)
**⏱ Read time:** 2 min

Microsoft disclosed CVE-2026-69836 (CVSS 10.0), a deserialization-of-untrusted-data RCE in Entra ID (formerly Azure AD), confirmed exploited in the wild — but already fully mitigated server-side, with no customer action required. No details on how exploitation was discovered, who did it, or how long it ran.

**Why it matters:** A 10.0 in the identity backbone of most enterprises — and the "already mitigated" framing means detection of the exploit chain is the only way to know if tenants were hit.

### [📄 Rust Supply Chain Attack Puts Build-Time Malware in Crates with 245 Million Downloads](https://thehackernews.com/2026/08/rust-supply-chain-attack-puts-build.html)
**⏱ Read time:** 2 min

A compromised maintainer account published malicious versions of three widely used crates — arrayref 0.3.10, internment 0.8.7, append-only-vec 0.1.9 — on August 20, each adding a typosquatted dependency (proc-macro1) whose build script downloaded and executed a remote payload at compile time. All were yanked within 86–107 minutes; RustSec advisories claim no evidence of actual usage, and no CVE exists. SecurityWeek links the attack to North Korean hackers. Developers should pin arrayref ≤0.3.9 and scan `~/.cargo/registry/cache` for deleted artifacts.

**Why it matters:** Build-time execution means merely resolving a dependency runs the payload — and AI-assisted malware is making typosquat/supply-chain campaigns cheaper to run at scale; the same pattern will hit agent package ecosystems (MCP servers, skills).

### [📄 New Cryptographic Context Injection Attack Could Let Web Pages Steal Grok Chat Data](https://thehackernews.com/2026/08/new-cryptographic-context-injection.html)
**⏱ Read time:** 2 min

Adversa AI disclosed "Cryptographic Context Injection": a web page ships an encrypted JSON payload plus key material; Grok's own Python code-execution runtime decrypts it (PBKDF2 + AES-256-GCM) and follows the recovered instructions, exfiltrating the user's name, approximate location, subscription tier, and live prompts to an attacker server — with no confirmation step. No patch or CVE; 40% success rate across 20 attempts since June (tested on Grok 4.5 Fast at grok.com).

**Why it matters:** Encrypted instructions defeat content classifiers at inspection time — a blueprint for smuggling instructions past safety filters into any agent with a code runtime, including Manny's own targets.

### [📄 Attackers Exploit Zimbra SNMP Flaw for Unauthenticated Remote Code Execution](https://thehackernews.com/2026/08/attackers-exploit-zimbra-snmp-flaw-for.html)
**⏱ Read time:** 2 min

CERT Polska reports active exploitation of CVE-2026-73570 (CVSS 8.9), a command injection in Zimbra Collaboration before 10.1.20 when the optional zimbra-snmp package is installed — unauthenticated attackers can execute OS commands as the Zimbra user via crafted SMTP requests during SNMP notification processing. **Why it matters:** Mail servers remain the highest-value, most-targeted edge — and this is the second Zimbra campaign this month after Laundry Bear's ZimRe phishing, reinforcing mail-to-RCE as a standing risk for any client running Zimbra.

**⏱ Read time:** 2 min

watchTowr observed in-the-wild exploitation of CVE-2026-19478 (CVSS 9.4), a code injection via GraphQL directive letting unauthenticated attackers delete public projects, forge merge records, and ban maintainers — reproduced within minutes of disclosure, with exploitation hitting its honeypot network days later. watchTowr's Jake Knott: AI-enabled attackers are compressing disclosure-to-exploitation so much that "waiting until the next patch cycle is often too late." ## 🔌 MCP / AI AGENTS

### [📄 Critical Flaw in n8n: Workflow-to-RCE chain](https://thehackernews.com/2026/08/threatsday-gogs-100-rce-n8n-workflow-to.html)
**⏱ Read time:** 2 min

CVE-2026-33696 (CVSS 9.4): prototype pollution in n8n's XML and GSuiteAdmin nodes lets any authenticated user with workflow create/modify permissions achieve RCE as the n8n process user (researcher Simon Koeck). Fixed in 2.14.1, 2.13.3, and 1.123.27. Prototype pollution alone can crash the instance; the chain yields full code execution.

**Why it matters:** n8n is the de facto agent/workflow orchestrator for thousands of orgs — a workflow-to-RCE path means compromising one workflow (e.g., via injected prompt or malicious node config) hands attackers the whole agent runtime.

### [📄 AWS limits AI agents' data access, even when manipulated](https://www.helpnetsecurity.com/2026/08/20/aws-ai-agents-access-controls/)
**⏱ Read time:** 2 min

AWS published a reference architecture for Bedrock AgentCore that propagates the end user's authorization context through agents so enforcement happens in downstream services (DynamoDB, SaaS, knowledge bases) instead of trusting the agent itself: "The agent acts as an orchestrator, not a gatekeeper." The design keeps access controls intact even if the agent is manipulated (prompt injection), because the data plane re-checks the original user identity.

**Why it matters:** This is the right pattern for agent security — never let the model be the enforcement point — and a concrete model Manny can push clients toward instead of agent-side filtering.

### [📄 Isolated-vm Flaw Lets Sandboxed JavaScript Escape to Host for Potential RCE](https://thehackernews.com/2026/08/isolated-vm-flaw-lets-sandboxed.html)
**⏱ Read time:** 2 min

Endor Labs disclosed GHSA-864f-rcv7-6rh4 (no CVE yet): a type confusion in isolated-vm's ExternalCopy `transferList` handling lets code inside the V8 sandbox corrupt host memory, escalating from a single `ivm.Reference` to a sandbox escape. Affects all versions ≤7.0.0; patched in 6.2.0 and 7.0.1. isolated-vm (~1M npm downloads/week) is a common choice for running untrusted JS in agent harnesses and browser-adjacent runtimes.

**Why it matters:** Agent sandboxes are the last line of defense against malicious tool output and skills — a sandbox escape turns "untrusted code contained" into host RCE.

## 📄 PAPERS

### [MaliciousSkillBench: A Comprehensive Benchmark for Malicious Agent Skill Detection](https://arxiv.org/abs/2608.19901)
**Authors:** Yue Wang, Yi Liu, Gelei Deng, Ying Zhang, Yuekang Li, Zhenyu Chen, Leo Zhang | **Published:** 2026-08-20

Consolidates 13 public sources into 9,740 normalized Skills (7,505 malicious, 2,235 benign) across 11 attack categories, then benchmarks three learned detectors and three Skill scanners. Learned detectors hit 0.882–0.932 Random Macro-F1 but collapse to 0.653–0.665 under Source-Disjoint evaluation; scanners trade false positives for recall. Conclusion: reliable malicious-Skill detection needs cross-source coverage and joint attack-detection/benign-over-flagging measurement.

**Full breakdown:** [papers/2026/08/maliciousskillbench-malicious-agent-skill-detection.md](https://github.com/manthanghasadiya/intel/blob/main/papers/2026/08/maliciousskillbench-malicious-agent-skill-detection.md)

### [Inadvertent Context Leakage in Language Models](https://arxiv.org/abs/2608.19857)
**Authors:** Jaiden Fairoze, Neal Mangaokar, Kamalika Chaudhuri, Sanjam Garg, Saeed Mahloujifar | **Published:** 2026-08-20

Shows secrets sitting in an agent's context window leak through benign outputs even when the model correctly refuses direct extraction: 2-digit in-context secrets reconstruct near-perfectly, 4-digit at 82% exact match across eight proprietary models. More capable models leak more. Practical attacks include a classifier inferring health/financial predicates from routine outputs and an RL-trained adversary extracting full SSNs from a production-style agent.

**Full breakdown:** [papers/2026/08/inadvertent-context-leakage-language-models.md](https://github.com/manthanghasadiya/intel/blob/main/papers/2026/08/inadvertent-context-leakage-language-models.md)

### [EchoCoT: Extracting Hidden Chain-of-Thought from Large Reasoning Models](https://arxiv.org/abs/2608.20055)
**Authors:** Yiting Qu, Ziqing Yang, Chi Cui, Ye Leng, Junjie Chu, Yang Zhang | **Published:** 2026-08-20

A multi-step black-box attack that extracts hidden CoTs near-verbatim through API interactions, exploiting a "reasoning replay surface" between tool calls. Up to 66.4% near-verbatim extraction success on open-source LRMs (≥90% token match), generalizing to 80% on unseen datasets; on Gemini-2.5 it extracted 33,463 of a 32,948-token target CoT. Makes hidden-CoT extraction a practical security risk for proprietary reasoning assets.
