### [📄 Ruby 4.0 Marshal.load universal RCE gadget chain disclosed](https://gbhackers.com/ruby-4-0-marshal-load-rce-gadget-chain/)
**⏱ Read time:** 2 min

elttam published a universal deserialization gadget chain: a single unsafe `Marshal.load` on attacker-controlled data yields RCE on Ruby 4.0.6 — and works unchanged back to Ruby 3.3. The chain combines RubyGems autoloading (`Gem::SpecFetcher`) with `Time` deserialization to pull a compressed payload from an attacker-controlled HTTPS server, then `Gem::StubSpecification` → `Gem::Specification.load` evaluates it. No app-specific dependencies or pre-existing files required.

**Why it matters:** Any Ruby service deserializing untrusted data is a one-gadget RCE — worth an immediate audit of Marshal usage in agent tooling and CI components.

### [📄 'Download More RAM' attack bypasses Windows VBS/HVCI, disables Defender](https://gbhackers.com/download-more-ram-attack-bypasses-windows-vbs/)
**⏱ Read time:** 2 min

Presented at USENIX Security 2026 and tracked as CVE-2026-23670, the technique abuses writable Serial Presence Detect (SPD) EEPROMs on consumer DDR4/DDR5 DIMMs. An attacker with local admin rewrites the reported memory geometry — demonstrating ~2x fake capacity — which undermines VBS/Hypervisor-Protected Code Integrity and lets them disable Microsoft Defender and third-party EDR.

**Why it matters:** Hardware-config weaknesses defeat the OS-level integrity primitives that EDR relies on — kernel-adjacent agent sandboxes on Windows inherit this exposure.

## 🔌 MCP / AI AGENTS

### [📄 Customhouse: deterministic MCP proxy that blocks agent exfiltration](https://github.com/vineetpant/customhouse)
**⏱ Read time:** 2 min

New open-source (Rust, Apache-2.0) reference monitor for MCP: it tracks the provenance of every input and deterministically blocks money-moving or data-egress tool calls in any session that has received untrusted content — no model in the decision path, no payload pattern-matching, so rewording/base64 obfuscation can't evade it. Includes rug-pull protection (a server swapping a tool definition is withheld until repinned), an append-only ledger of agent tool calls, and deny-by-default flow enforcement on payment/egress sinks.

**Why it matters:** This is exactly the provenance-based containment layer MCP deployments need — worth benchmarking against the poisoned-file → exfiltration flows in the ATOBench paper below.

### [ATOBench: Tracing How Autonomous Penetration-Testing Agents Verify Vulnerabilities When Target Evidence Lies](https://arxiv.org/abs/2608.12996)
**Authors:** Qiyang Chen, Yixi Li, Fengwei Zhang, Junlin Liu | **Published:** Aug 13, 2026 (cs.CR)

An evaluation framework that makes pentest agents' verification process observable: it injects transformed (deceptive) target responses at runtime and pairs each episode with a native one, aligned at first contact. Across 450 episodes (5 model routes incl. GPT-5.5, DeepSeek-V4-Pro, Kimi-K2.6, GLM-5.2, Qwen3.7-Max running through Claude Code), it shows increased search activity can mask a broken verification chain, and successful recovery depends on finding usable evidence and preserving it through the report.

**Full breakdown:** [papers/2026/08/atobench-pentest-agent-verification.md](link)

### [Beyond Handcrafted Security: Towards Self-Evolving Defense for LLM Agents (HARD)](https://arxiv.org/abs/2608.12977)
**Authors:** Jiajun Ruan, Peiyang Li, Yukun Chen, Fengting Li, Chao Feng (U. Minnesota, Ant Group, Tsinghua, Zhejiang U.) | **Published:** Aug 13, 2026 (cs.CR)

HARD frames runtime defense as optimization over the agent harness (context construction + action interpretation) and lets LLM evolvers autonomously refine defense artifacts from failure traces. On AgentCanary, HARD-Both cuts attack success rates to 15.4%/1.0%/6.7%/10.2% across DPI/IPI/memory-poisoning/skill-poisoning (handcrafted: 13–66%) while keeping benign utility at 91.9–95.0%.

**Full breakdown:** [papers/2026/08/hard-self-evolving-runtime-defense.md](link)
