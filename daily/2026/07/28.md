## 🤖 AI NEWS

### [📄 Microsoft Unveils MAI-Cyber-1-Flash, Its First Cybersecurity AI Model](https://www.securityweek.com/microsoft-unveils-mai-cyber-1-flash-its-first-cybersecurity-ai-model/)
**⏱ Read time:** 3 min

Microsoft dropped its first domain-specific cybersecurity AI model, MAI-Cyber-1-Flash, designed to identify challenging vulnerabilities in complex code. Integrated into the MDASH multi-agent harness (100+ specialized AI agents orchestrated across frontier and distilled models), the model handles 90% of tasks, reserving the 10% hardest for GPT-5.4. In CyberGym testing, MAI-Cyber-1-Flash (paired with MDASH + GPT-5.4) topped Google's 3.5 Flash Cyber, OpenAI's GPT-5.6 Sol, and Anthropic's Mythos 5 at vulnerability discovery. Microsoft claims a 50% cost savings vs. their previous best MDASH configuration. Project Perception (the agentic security offering wrapping all this) enters public preview August 3.

**Why it matters:** A major vendor just bet that narrow, cybersecurity-specific models + multi-agent orchestration beats general-purpose frontier models on security tasks — at half the cost. Manny should watch whether this architecture (specialized model + agent harness) becomes the template for AI security tools.

### [📄 AI Helped Develop Linux Traffic-Control Race Into Full Root Exploit](https://thehackernews.com/2026/07/researcher-says-ai-helped-develop-linux.html)
**⏱ Read time:** 3 min

STAR Labs researcher Lee Jia Jie used AI assistance to find, analyze, and write a working exploit for CVE-2026-53264 (CVSS 7.8), a use-after-free race in the Linux kernel's network traffic-control subsystem that escalates local users to root. The exploit targets CentOS Stream 9 and succeeds in 10/10 test runs (9–111 seconds). AI helped with vulnerability discovery, KASAN proof-of-concept generation, and race-window optimization — though Lee notes AI still has "many blind spots" and human judgment was required throughout. The upstream fix landed June 1, 2026, and has been backported to stable branches. Full exploit source code is now public.

**Why it matters:** This is real evidence of AI accelerating end-to-end exploit development, not just bug-finding. The researcher didn't disclose which model or prompts were used, making independent benchmarking impossible — but the pattern is clear.

**Exploit/PoC:** [STAR Labs public exploit code](https://thehackernews.com/2026/07/researcher-says-ai-helped-develop-linux.html)

### [📄 ChatGPT Starts Blocking Direct Requests to Copy an Author's Style](https://arstechnica.com/ai/)
**⏱ Read time:** 2 min

OpenAI has updated ChatGPT to block direct requests asking it to write "in the style of" a specific author. The change appears aimed at reducing copyright liability from style mimicry — an area where creators and publishers have sued AI companies for reproducing stylistic signatures without consent. Legal experts note ChatGPT can still capture "broad qualities" of a style, so the practical effect may be limited.

**Why it matters:** This is a defensive move against the wave of creator lawsuits over style replication. For Manny's security work: expect similar "refusal hardening" in AI safety guardrails to become a cat-and-mouse game, with attacker prompts evolving to bypass.

### [📄 NVIDIA Cosmos-H-Dreams: Real-Time Generative Simulation for Surgical Robotics](https://huggingface.co/blog)
**⏱ Read time:** 2 min

NVIDIA released Cosmos-H-Dreams, a real-time generative simulation framework for surgical robotics. The system uses Cosmos world model technology trained on surgical video data to generate synthetic training environments for robot-assisted surgery. The framework is open-sourced on Hugging Face and targets the intersection of physical AI and healthcare robotics.

**Why it matters:** An indicator of how rapidly generative simulation is moving into domain-specific physical applications. The same architecture concept (world model + domain data → synthetic training) could be adapted for security simulation environments.

### [📄 Critical TeamCity Flaw: Unauthenticated RCE via Agent Polling (CVE-2026-63077, CVSS 9.8)](https://thehackernews.com/2026/07/critical-teamcity-flaw-could-let.html)
**⏱ Read time:** 2 min

JetBrains patched CVE-2026-63077 (CVSS 9.8) affecting all TeamCity On-Premises versions. An unauthenticated attacker with HTTP(S) access can bypass authentication checks via the agent polling protocol and execute arbitrary OS commands with TeamCity server process privileges. Fixed in versions 2025.11.7 and 2026.1.3. TeamCity Cloud was already patched. Discovered and reported by Antoni Tremblay on July 10, 2026.

**Why it matters:** TeamCity is the CI/CD backbone for many development pipelines — a pre-auth RCE is a supply chain nightmare. Active scanning for exposed TeamCity servers should start immediately.

**Exploit/PoC:** No public PoC disclosed as of July 28, but CVSS 9.8 suggests relatively straightforward exploitation.

## 🔌 MCP / AI AGENTS

### [📄 n8n Sandbox Escape Lets Workflow Editors Run OS Commands as n8n Process (CVSS 8.7)](https://thehackernews.com/2026/07/n8n-sandbox-escape-lets-workflow.html)
**⏱ Read time:** 4 min

Security Joes found an expression-sandbox escape in n8n (CVSS 4.0: 8.7) that lets authenticated workflow editors execute OS commands on the server. Two blind spots in the sandbox rewriter — an arrow-function gap and a property-inspection bypass — let attackers recover `process.mainModule`, load `child_process`, and run arbitrary commands. Affects n8n versions before 1.82.0 and 0.244.0. n8n fixed it on July 22. This follows a 9.4-rated escape in February (CVE-2026-27577) that was supposedly patched. The flaw was found while probing the February fix for a bypass.

**Why it matters:** n8n is increasingly used as the orchestration layer for AI agents and workflow automation. This is the second sandbox escape in six months — the pattern suggests expression-sandbox security in agent workflow tools is systematically under-tested and under-hardened.

### [📄 Hush Security Raises $30 Million for AI Agent Governance](https://www.securityweek.com/hush-security-raises-30-million-for-ai-agent-governance/)
**⏱ Read time:** 2 min

Manny should track this space as it directly impacts how we secure (and potentially attack) agent deployments.

## 📄 PAPERS

### [Mask2Shield: Strengthening LLM Safety against Neuron-Pruning Attacks](https://arxiv.org/abs/2607.23015)
**Authors:** Ying JinCheng, Minghui Xu, Yinhao Xiao, Xiuzhen Cheng, Wencheng Yang | **Published:** July 28, 2026

Introduces a masked-forward alignment method that trains models to maintain safety refusal behavior even when critical "safety neurons" are pruned. Reduces successful recomputed pruning attacks from 80-279 to 1-44 out of 313 prompts while preserving capability benchmarks. Directly relevant to AI red team work — attacks that disable safety neurons via pruning are a growing vector.

**Full breakdown:** [papers/2026/07/mask2shield-llm-safety-neuron-pruning.md](https://github.com/manthanghasadiya/intel/blob/main/papers/2026/07/mask2shield-llm-safety-neuron-pruning.md)

### [Same Question, Different Answers: Evaluating LLM Reliability Beyond Accuracy](https://arxiv.org/abs/2607.22554)
**Authors:** Kazem Faghih, Yize Cheng, Shoumik Saha, Mobina Pournemat, Armin Gerami, Soheil Feizi | **Published:** July 28, 2026

Studies how LLM answers change under meaning-preserving paraphrases. Across 4 benchmarks and 13 models, they find instance-level instability reaching 23% mismatch rates on the same question rephrased. Single-prompt correctness is a poor reliability indicator. A simple self-paraphrasing strategy partially recovers latent knowledge.

**Why it matters:** For Manny's AI red team work, this quantifies a key attack surface: prompt variations that flip model outputs reveal exploitable inconsistencies that can be weaponized.

**Full breakdown:** [papers/2026/07/llm-reliability-paraphrase-inconsistency.md](https://github.com/manthanghasadiya/intel/blob/main/papers/2026/07/llm-reliability-paraphrase-inconsistency.md)

### [ReCon: A Resource-Constrained Benchmark for LLM-Based Cybersecurity Compliance](https://arxiv.org/abs/2607.22885)
**Authors:** Rohit Negi, Rishik Jain, Soumyo V Chakarborty, Amit Negi, Sandeep K Shukla | **Published:** July 28, 2026

A new benchmark evaluating how LLMs handle cybersecurity compliance analysis under resource constraints (limited context, retrieval pipelines, etc.). Tests across ingestion and retrieval pipelines. Provides a standardized way to assess whether LLMs can reliably interpret security policies and compliance requirements.

**Why it matters:** With AI agents increasingly tasked with security compliance decisions, understanding their failure modes under realistic constraints is critical. This benchmark offers a framework for testing that.
