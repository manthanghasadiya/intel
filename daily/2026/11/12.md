## 🔐 SECURITY

### [📄 4,837 hijacked GitHub accounts planted a CI secret stealer in 1,806+ repositories](https://thehackernews.com/2026/11/4837-hijacked-github-accounts-ran-ci.html)
**⏱ Read time:** 4 min

Starting Tuesday, an attacker used stolen credentials for 4,837 GitHub accounts to open PRs titled `docs: dependency audit notes` from `wfx-docs` branches in 61,764 repositories as a write-access probe; where it stuck, a stealer was pushed in at least 1,806 repos, and SafeDep counted 8,093 repos with malicious commits between 12:46 UTC Tuesday and 04:36 UTC today. In 7,309 repos the stealer was appended to an existing workflow, in 771 it arrived as an npm `postinstall` hook; the change was usually reverted within minutes and the run logs deleted. It harvests Actions secrets and variables, `GITHUB_TOKEN`, OIDC and runtime tokens, **keys for AI services**, secrets in runner process memory, and AWS/Azure/GCP/Kubernetes/npm/PyPI/SSH credential files — then exchanges OIDC tokens for cloud sessions and exfils to `194.150.166.244:8080`, `18.143.168.96:8080`, `153.75.82.159:8080` or Telegram.

**Why it matters:** Every secret a CI workflow can read must now be treated as stolen — including the model API keys that fund your red-team agents. Detection strings are in the article; the branch name and PR title are the cheapest canaries you will get all month.

### [📄 Apache mod_http2 RCE (CVE-2026-119618, CVSS 9.8) — 2.4.71 is out, Debian stable is not](https://thehackernews.com/2026/11/critical-apache-http2-flaw-could-let.html)
**⏱ Read time:** 3 min

Unauthenticated remote code execution in `mod_http2`, affecting httpd 2.4.55–2.4.70 and standalone mod_h2 2.0.8–2.0.42; fixed in 2.4.71, released yesterday. Red Hat's advisory states "public research has demonstrated a reliable exploit" against a default config with HTTP/2 enabled, while Wiz says no public exploit exists and no in-the-wild activity has been seen. RHEL 9/10 shipped fixes yesterday but rate it Important, not Critical, because their builds give each stream its own allocator; Debian bookworm/trixie/forky remain vulnerable and Amazon Linux is pending.

**Why it matters:** Only hosts with `Protocols h2`/`h2c` are exposed — inventory that directive across every vhost before you assume you are unaffected.

### [📄 Google Cloud: three AMD Turin side channels leak data across processes inside a VM](https://thehackernews.com/2026/11/google-cloud-warns-three-amd-turin-cpu.html)
**⏱ Read time:** 3 min

Google says C4D, N4D, H4D, Z4D and G4 instances (including C4D/Z4D bare metal) on 5th-gen EPYC "Turin" are affected by three Transient Scheduler Attacks: TSA-SQ (CVE-2024-36350), TSA-L1 (CVE-2024-36357) and the new CVE-2026-0004, which Xen calls TSA-Fill and which can leak L1 data-cache contents. Cross-VM and VM-to-host mitigations are already applied; inside a VM the flaws can expose other processes or the kernel. AMD corrected itself — it had previously said Zen 5 was not vulnerable to TSA-SQ/TSA-L1.

**Why it matters:** The customer-side fix is a guest kernel patch **plus a stop-and-start** — Google is explicit that a guest reboot is not enough, so multi-tenant build agents need a maintenance window, not a kernel livepatch.

### [📄 Token built an agent that broke every rule they sell — then documented the fix](https://thehackernews.com/2026/11/we-built-agent-that-broke-all-of-our.html)
**⏱ Read time:** 3 min

Token's browser agent "Rehearsal" clicks, filters and fills forms inside the user's authenticated session, and the server cannot distinguish its clicks from the user's because nothing in a session cookie identifies the session driver — no actor, no delegation, no task scope. Their remedies are worth copying: lock and clearly attribute control while the agent moves, log every action including blocked ones, hold the agent's reach strictly below the user's (read-only dashboards, no secret fields, never re-send a refused call), and use accessibility labels as the page map instead of DOM scraping.

**Why it matters:** If your harness drives a browser tab, you are the delegation gap — the app sees a human and an over-broad scope, and only you can prove which was which.

### [What a CAGE 4 Score Measures: An Audit of a Learned Cyber-Defense Benchmark, Its Reference Defenders, and the Tables Built on Them](https://arxiv.org/abs/2611.14068)
**Authors:** James Rice, Ji Hwan Park, Andres Kwasinski | **Published:** Nov 10, 2026

Reproduces CAGE Challenge 4's KEEP and H-MARL Expert defenders in a pinned container and finds the simulator silently discards actions issued while an agent is busy — then charges for them anyway — costing 99.58 and 145.98 points per episode when the undocumented busy check is disabled. It also shows 88.9% of per-episode outcome variance is the policy's own sampling draw, not the defense.

### [LEASH: Stay Safe in Agentic Robotics](https://arxiv.org/abs/2611.14115)
**Authors:** Qinfeng Zhu, Weiguang Zhao, Ke Sun, Xihao Guo, Yunxi Jiang, Rui Zhang, Lei Fan, Kaizhu Huang | **Published:** Nov 10, 2026

Introduces RoboRisk — 92 simulated and 13 physical-robot safety tasks across refusal, plan repair, execution-time hazard, injection and sequential memory — and finds six frontier models (GPT-6 Astra/6.1 Sol/6 Luna, Claude Opus 5.5, Gemini 4 Argon, Grok 4.7) generally show high harm rates. LEASH adds task, action and commit gates driven by a decision model sharing one safety policy, cutting harm across all six while largely preserving completion.

## 🔥 HOT TAKE + CONTENT IDEA

**Write "Your CI runner is an AI-key vending machine" tonight.** The `wfx-docs` campaign is the first mass-scale proof that the fastest path to a victim's model API keys is not a prompt injection — it is a pull request. The stealer explicitly targets keys for AI services and reads credentials out of runner process memory, which means your `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` sitting in an Actions secret is now an exfil target with a documented IOC list. Publish a 10-minute detection post: (1) grep org-wide for branch `wfx-docs`, PR title `docs: dependency audit notes`, commit `ci: refresh build cache`; (2) flag any workflow that grew ~1,500 lines overnight; (3) alert on `postinstall` hooks added under `chore/[a-z0-9]{8}`; (4) block egress to the three exfil IPs on port 8080; (5) rotate every secret any workflow can read, including model keys, and treat any machine that ran `npm install` on a hit commit as compromised. Pair it with the CAGE 4 audit for the second half: benchmark-topping claims from agent vendors are measuring a sampling draw, so ask for the artifact, seeds and adversary — not the leaderboard.
