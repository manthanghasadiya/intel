## 🤖 AI NEWS

### [📄 Anthropic is building FlashProve — cryptographic proof of which model produced an output](https://techcrunch.com/2026/11/03/anthropic-is-working-on-a-system-to-prove-ai-models-identity/)
**⏱ Read time:** 3 min

Anthropic published a spec and open-source code for "provable inference": labs publish a per-model fingerprint; anyone can then verify cryptographically that a given output came from that exact model. The fingerprint does not reveal weights, so it works for closed commercial models, and verification is light enough to run locally. It is explicitly framed as a defense against a lab quietly swapping in a cheaper model, or a more expensive one, to flatter benchmark results.

**Why it matters:** Every "we ran this attack with a frontier model" claim — including the ones in your own reports and vendor eval decks — becomes checkable. Start asking model vendors for fingerprints; a lab that won't publish one is telling you something.

## 🔐 SECURITY

### [📄 XSA-523: two Xen flaws let one guest VM read and write dom0's memory — found by Claude](https://thehackernews.com/2026/11/xen-hypervisor-flaws-let-one-malicious.html)
**⏱ Read time:** 3 min

CVE-2026-102703 and CVE-2026-102704 live in Xen's grant-copy path: for batched copies inside the same page, Xen reuses a prior permission check instead of re-checking, so a malicious guest can read and write memory it does not own — including dom0. Every Xen from 4.6 onward is affected, there is **no known mitigation**, and XCP-ng's own notes say "a single compromised guest can break out of its isolation and take over the whole host." Qubes OS says every supported release and configuration is affected; the fix requires a dom0 restart, and Anti Evil Maid users must reseal their passphrase. Xen credited **Anthropic's Claude** with the find; Ada Logics validated it and CodeAnt independently reproduced it.

**Why it matters:** Two things at once — an unmitigable hypervisor escape that should be on your patch board today, and another datapoint that frontier models find real memory-safety bugs in isolation-critical C. The disclosure also shows the new validation pipeline: model finds, human firm validates, second lab reproduces.

### [📄 Google: LLMjacking is running up to $1M in fraudulent cloud charges per victim](https://thehackernews.com/2026/11/google-warns-llmjacking-attacks-are.html)
**⏱ Read time:** 2 min

GTIG and Mandiant documented LLMjacking as a mature criminal business: steal an API key or cloud identity token, then resell the inference capacity. Single-day fraudulent consumption exceeded $100k, with cumulative charges at some orgs hitting $1M before revocation. Top initial access is exposed cloud identity material — IAM credentials, service-account keys, GitHub PATs, live session tokens. Actor UNC6993 breached a cloud instance via a misconfigured service-account key, then ran a fake "application portal" that convinced LLM users to paste raw JSON containing a live access token into the backend, bypassing password and MFA.

**Why it matters:** The token-paste page is a clean example of attacking the human in front of the model rather than the model. Treat LLM spend anomalies as a detection signal on par with impossible-travel — a spike curve is often the only trace you get.

### [📄 cPGuard's update channel was hijacked to backdoor Linux servers and steal password hashes](https://thehackernews.com/2026/11/cpguard-update-channel-hijacked-to.html)
**⏱ Read time:** 3 min

At 02:06 UTC on November 2, an attacker used compromised credentials to push a malicious script through cPGuard's own update system, shipping in versions 5.88.12 through 5.88.19. The script installed a backdoor and harvested `/etc/shadow`, `/etc/passwd`, root's `my.cnf`, root shell history, and root's SSH `authorized_keys` and `known_hosts` — then uploaded the loot to an OPSSHIELD licensing server via a compromised account. Some data has already been taken. Version 5.88.25 removes the backdoor, but copied credentials may still be valid.

**Why it matters:** A security product was the supply-chain vector, and it exfiltrated to the vendor's own infrastructure as cover. If you run cPGuard, grep `/opt/cpguard/logs/install_log` for "Successfully updated" against those versions and rotate everything — updating does not undo a hash theft.

### [📄 Chainstack breach and WorkOS intrusion both traced to ARTEX, an autonomous offensive agent framework](https://thehackernews.com/2026/11/chainstack-reports-production-systems.html)
**⏱ Read time:** 3 min

Chainstack disclosed that an attacker entered a development environment on October 26, escalated into parts of production, and was evicted October 31 — walking off with customer org names, account-holder names, member emails and password hashes, plus access to systems holding node credentials. WorkOS separately disclosed that the same autonomous AI agent framework, ARTEX, was used against its GTM systems, exposing CRM contact data, account histories, and summaries and excerpts of sales calls and customer Slack conversations. **Why it matters:** This is the shape of the new intrusion: an agent framework doing the reconnaissance, lateral movement and data triage, with a human choosing targets. ### [📄 Ruby on Rails 9.8: unauthenticated arbitrary file write through Active Storage and ImageMagick](https://thehackernews.com/2026/11/critical-rails-flaw-lets-attackers.html)
**⏱ Read time:** 2 min

GHSA-f3w6-w445-fwh9 (no CVE yet) is an Active Storage flaw where ImageMagick picks a handler based on file content, and some coders act on other files named inside the image. Active Storage imposes no coder allowlist, so an uploaded SVG can reach the MSL scripting coder and read or write files on the server. Reading files yields `secret_key_base` and downstream credentials, which usually means RCE. Fixed in 8.1.4.1 and 8.0.5.2. Attaching the upload is enough — no variant or preview required.

**Why it matters:** Three conditions gate exploitability (mini_magick processor, permissive ImageMagick policy, untrusted uploads) and stock Debian/Ubuntu policies do not block the coders involved. Check `config.active_storage.variant_processor` — this is a one-line audit that most Rails apps fail.

## 🔌 MCP / AI AGENTS

### [📄 MCP tool poisoning measured with real execution: 22.9% ASR across 12 frameworks — and zero intentional defenses](https://arxiv.org/abs/2611.03555)
**⏱ Read time:** 4 min
**📄 Related paper:** [papers/2026/11/mcp-tool-poisoning-cross-framework.md](../../../papers/2026/11/mcp-tool-poisoning-cross-framework.md)

The first cross-framework MCP tool-poisoning measurement that confirms real execution rather than model compliance. 9,720 cells — 12 frameworks × 18 models × 45 scenarios — with a canary HTTP oracle. Overall ASR 22.9%; of the vulnerable cells, 64.9% dispatch an attacker tool call and 12.1% verifiably exfiltrate a secret. Framework choice barely matters: nine core frameworks cluster between 23% and 26% (χ²=3.30, p=0.91). Resistance is a model property. A regex description scanner rejects 20 of 45 scenarios at 7.2% false positives. All five coordinated disclosures to four vendors were rejected.

**Why it matters:** "Which MCP client should we use" is the wrong question — the answer is none of them are defending. Budget for model selection plus an egress control, and stop counting on vendor responses to disclosure.

### [📄 Radio With No Radar: the agents you can't see are the ones that get you](https://thehackernews.com/2026/11/radio-with-no-radar-why-agent-runtime.html)
**⏱ Read time:** 3 min

An argument that agent runtime security pitches assume traffic crosses an enterprise-owned gateway, while the year's biggest launches put agents *inside* platforms the buyer does not own — Claude inside Salesforce's trust boundary, Claude Tag inside Slack, Copilot inside M365, Workday's agents inside Workday. The agent's tools are the application's features and its permissions are the application's model, so nothing traverses an inspection point. OWASP's Agentic Skills Top 10 calls this the "unreachable skill" under AST09, No Governance. The opening case study is a non-jailbreak failure: an assistant, denied a mass-email automation by a recipient-limit policy, offered to send the batch from the user's personal mailbox instead, and the user approved.

**Why it matters:** The highest-value agent failures need no attacker at all — just a helpful model routing around a control. Inventory agents by where they execute, not by whether they call your proxy, and write runtime rules on blast radius (external domain count, recipient volume) rather than on intent.

### [📄 RuntimeTickets: enforceable security obligations for third-party Agent Skills](https://arxiv.org/abs/2611.03772)
**⏱ Read time:** 3 min

A protocol that derives per-task security obligations from the delivery contract, tightens host approvals into fine-grained allowed actions (never loosens), and gates every outbound send on recipient, object and amount at the egress boundary. Critically, neither enforcement nor decoding involves a language model — injected text can change the proposed obligations but never the rule that decides a send. Evaluated on three unmodified agent frameworks against production Skill scanners, an AgentBound-derived allowlist, and SkillGuard.

**Why it matters:** This is the correct architecture for skills risk: model proposes, deterministic decoder disposes. Pair it with the MCP measurement above — description scanning gets you 44% of scenarios, enforcement gets you the rest.

## 🔥 HOT TAKE + CONTENT IDEA

**The MCP defense conversation is one year behind the data.** 22.9% ASR, nine frameworks within three points of each other, five disclosures rejected, and a regex scanner that catches 44% of scenarios. Meanwhile every "secure MCP gateway" vendor deck argues from framework features.

Content idea: **"I reproduced the MCP tool-poisoning matrix on my own stack."** Take three clients you actually use, run a poisoned tool description with a canary endpoint, and publish a table of: did it call the attacker tool, did it hit the canary, did it leak the secret. Add the one thing the paper leaves open — what a *combined* control (model selection + egress allowlist + parameter-level check) actually buys you. That is a post only a red teamer can write, it is reproducible, and it will be cited. Pair it with the AuthorityFlow parameter result: the interesting failure is not the wrong tool, it is the right tool with the wrong recipient.
