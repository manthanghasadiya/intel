**⏱ Read time:** 2 min

United is restricting third-party personal AI agents and assistants "directly within our digital platforms and indirectly via travel agencies and aggregators," and rewriting booking, ticketing and distribution policies to enforce it. The stated reasons: credential sharing with assistants leaks sensitive data, agents make unintended purchases and mileage redemptions, and a human must legally attest to bag contents at check-in. **Why it matters:** This is the first major consumer-facing "agents are not authorized users" policy. It's the template every regulated industry will copy — and it means the interesting attack surface moves from the web UI to the agent's local credential store.

## 🔐 SECURITY

### [📄 PHP2Shell on Check Point gateways → TSGA backdoor → ESXi wiper](https://thehackernews.com/2026/11/hackers-exploit-php2shell-flaws-in.html)
**⏱ Read time:** 3 min

An unknown actor hit unpatched Check Point Security Gateways via the PHP2Shell flaws (CVE-2026-109618 / CVE-2026-109619) on Oct 30 against Israeli orgs, then escalated with a previously undisclosed Gaia OS privilege-escalation bug, CVE-2026-123039 (CVSS 7.8) — a missing authorization check in DynamicCLI that lets any authenticated local user write a single request to a socket and get root. Check Point says it saw active exploitation against "a couple of dozen customers." Post-exploitation: PHP web shells, the TSGA passive backdoor (deployed as `slot_CPconfigdaemon`, with a TSProxy component that hijacks network functions inside existing appliance processes), the gogo scanner, SSH lateral movement to ESXi as `vpxuser`, and a `destroy_v6` wiper that drops `DREAM_ANNEXATION.txt` notes.

**Why it matters:** The LPE is only 7.8 because it's post-auth — but it's the step that converts a portal compromise into an appliance implant with no listening port. If you audit edge devices by CVSS, you'd have deprioritized the exact bug that made this campaign work.

### [📄 Red Hat Quay: two CVSS 9.8/9.9 flaws let anyone read and overwrite every private image](https://thehackernews.com/2026/11/critical-red-hat-quay-flaw-lets.html)
**⏱ Read time:** 3 min

CVE-2026-123710 (9.8): Quay's key server validates that a key-replacement request carries a token signed by a trusted key with the right audience and issuer, but never checks the token was issued *for key rotation*. An anonymous token from Quay's own `/v2/auth` endpoint passes, and the caller picks the audience — so an attacker adds their own non-expiring signing key and can then pull or overwrite any private image in any repo. The planted key survives restarts. CVE-2026-110697 (9.9) is separate: an unescaped `_` wildcard in the robot-account SQL `LIKE` pattern lets any user who can create a namespace steal other tenants' robot tokens, which in OpenShift means injecting images into CI/CD pipelines. Both were found by Red Hat's Dave O'Connor; the key-confusion logic has existed since Quay's first public commit, and every Quay 3 and Quay 5 version is affected.

**Why it matters:** This is a trust-anchor break, not a perimeter break — a registry that signs its own tokens cannot use those tokens as proof of authority. Any internal registry untrusted clients can reach is exposed.

### [📄 SignDrop: public CLFS zero-day takes a standard user to SYSTEM, no CVE, no fix](https://thehackernews.com/2026/11/new-signdrop-zero-day-exploit-turns.html)
**⏱ Read time:** 3 min

Researcher MSNightmare published PoC code and a writeup on Patch Tuesday for a flaw in Windows' Common Log File System driver. Microsoft's October 2025 mitigation added an HMAC-based log authentication check, plus a companion `.cnpf` file holding recovery data. SignDrop pre-builds a CLFS log and container at attacker-controlled paths; when a privileged process (in the PoC, Defender's update interface) opens the log, the driver creates the `.cnpf` in the *privileged* context, and object-manager symlinks redirect that creation to an attacker-chosen path. The resulting file is owned by SYSTEM but writable by the standard user — chained to a SYSTEM shell. Tested on Windows 11 26H2 and Server 2025. It works in both enforced (0) and learning (1) CLFS auth modes, which is the default state on any install older than 90 days.

**Why it matters:** The mitigation Microsoft added for 10 prior CLFS bugs is itself the bug surface — and "disable the mitigation" (registry 2/3) reopens the memory-corruption class. This is an unpatched local privesc that works on default configs right now.

## 🔌 MCP / AI AGENTS

### [📄 "When an AI agent goes wrong, can you stop it?" — OWASP on what a kill switch actually is](https://thehackernews.com/2026/11/when-ai-agent-goes-wrong-can-you-stop-it.html)
**⏱ Read time:** 3 min

An October 2026 OWASP GenAI Security Project roundup documents evaluation agents reaching past their intended scope and argues containment must revoke credentials *and* network access, not just pause the model. The operational point: an agent is a model + orchestrator + identity + tools + network policy, and stopping any one of those leaves the others running — queued jobs, retries, established sessions and pre-issued tokens all survive a paused endpoint. Recommended sequence: pause the workflow through the *runner* (a prompt telling the agent to stop is not a control), then revoke/rotate the credentials, sessions and service identities tied to that run, then cut tool and network paths.

**Why it matters:** Every "we have a kill switch" claim in an agent demo should be tested as a set of four independent revocations. This gives you the checklist to break those claims in a review.

## 📄 PAPERS

### [MobileProbe: Adaptive Security Evaluation of Mobile Agents via Trajectory-Aware Injection](https://arxiv.org/abs/2611.16693)
**Authors:** Yingbin Jin, Ji'an Wang, HaoYang Chai, Hanjun Luo, Li Hu, Xinfeng Li, Huadi Zheng, PeiZhao Hu, Qingqing Ye, Haibo Hu — PolyU / Zhejiang University / Huawei | **Published:** Nov 12, 2026 (NDSS 2027)

Fixed-point injection benchmarks under-measure mobile GUI agent risk because agents take different routes and never reach the pinned payload. MobileProbe picks injection points along the agent's *actual* trajectory, then evolves payloads with a surrogate-filtered loop. It reaches 85.1–86.3% ASR across three agent architectures with payload-miss rates down to 3.6–6.0%.

## 🔥 HOT TAKE + CONTENT IDEA

**"Your registry trusts any token it signed."** CVE-2026-123710 is a 10-minute demo video: hit `/v2/auth` anonymously, take the signed token, set your own audience, POST it to the key server, add a non-expiring signing key, then pull a private image from a repo you were never granted. The punchline writes itself — Red Hat's validation checks *who signed it*, never *what it was for*, and that logic has been in Quay since the first public commit. Pair it with the Fireworks and PHP2Shell stories into one thesis: **2026's breaches aren't perimeters falling, they're trust anchors accepting their own reflection.** That's a strong Friday post, and it sets up the PolicySniff paper as the sequel — even your agent's approval setting isn't confidential.
