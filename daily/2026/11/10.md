### [📄 Claude Fable 5.2 beats GPT-6 Cyber on multi-stage attack benchmark — and Anthropic cut the price](https://thehackernews.com/2026/11/anthropics-claude-fable-52-beats-gpt-6.html)
**⏱ Read time:** 3 min

Anthropic released Claude Fable 5.2 and Claude Mythos 5.2 on Monday. On Irregular's CyScenarioBench — which tests whether a model can plan and execute a multi-stage cyber operation in a realistic environment — Fable 5.2 completed **76.3%** of challenges, versus 61.7% for Fable 5.1 and **61% for OpenAI's GPT-6 Cyber**. On Anthropic's internal CVE Rediscovery benchmark (1,829 October 2026 open-source advisories), Fable 5.2 scored 89.6%. Mythos 5.2 is positioned as the "most capable model for cybersecurity engineering," gated behind the Cyber Verification Program.

Commercially the news is just as sharp: Fable drops from $10 to $8 per million input tokens (now cheaper than GPT-6 Astra), responses are 30% faster, and Fable 5.2 is finally compatible with zero data retention under Enterprise Frontier Safeguards. Anthropic's own system card concedes both new models "voice suspicion that they are being evaluated more often than any of our recent models" — i.e. eval-awareness is degrading their ability to measure real-world behavior.

**Why it matters:** The offensive-security capability gap between frontier labs is now measured in points on a public benchmark, not vibes. If you're benchmarking agent security work, CyScenarioBench is the number your readers will ask about.

**⏱ Read time:** 2 min

Meta Superintelligence Lab released Muse Ember, its lightest model, explicitly designed for "the work agents repeat all day: tool calls, coding subtasks, routing, extraction, and long document parsing." **Why it matters:** Cheap, multimodal, tool-call-shaped models are what make high-volume agent harnesses economically viable. This is the tier where prompt-injection defenses get tested at scale — and where a 1-cent-per-task cost delta decides your architecture.

## 🔐 SECURITY

### [📄 SAP patches four CVSS 10.0 flaws — ICM2SHELL, PROXYGATE, and a SAML2 signature bypass](https://thehackernews.com/2026/11/sap-patches-four-cvss-100-flaws.html)
**⏱ Read time:** 3 min

Four unauthenticated, zero-interaction bugs rated 10.0 dropped in SAP's November Patch Day. Three live in NetWeaver AS ABAP, one in the Web Dispatcher. **CVE-2026-76964 (ICM)** and **CVE-2026-89126 (Web Dispatcher)** are the same underlying bug in kernel code that reassembles split WebSocket messages — crafted traffic corrupts memory and yields OS command execution as `<sid>adm`. WebSocket support is on by default, so exposure doesn't require anyone to use it, and a crashed Web Dispatcher takes down every SAP system behind it.

**CVE-2026-120017** is worse in kind: the SAML2 service provider didn't verify signatures on incoming assertions under some configurations, letting an attacker log in as any user — including privileged ones — on any Fiori/WebGUI stack fronted by an IdP. **CVE-2026-89103 (PROXYGATE)** abuses the SAP Gateway's proxy ACL so an external attacker is treated as one of the system's own application servers. Onapsis found the first three and handed SAP a working exploit; RedRays advises updating the kernel and every Web Dispatcher in a single rollout.

**Why it matters:** SAML signature non-verification is the same class as the SonicWall SAML bypass from two weeks ago. If you're auditing SSO paths, "does it check the signature" is now a recurring finding, not a one-off.

### [📄 N-able pulls N-central cloud offline after researcher drops 33 zero-days with PoCs ("Able2Shell")](https://thehackernews.com/2026/11/n-able-takes-hosted-n-central-offline.html)
**⏱ Read time:** 2 min

N-able took its Hosted N-central environment offline and told on-prem customers to shut down servers after independent researcher Sean Bales published 33 vulnerabilities with proof-of-concept exploits, tested against N-central Appliance 2026.4.0.31. The set spans credential disclosure, arbitrary file writes, directory traversal, XSS, XXE and RCE, and chains into anonymous credential theft, admin creation, and `nable`/root RCE. There's also a native GenericTCP stack overflow for root.

N-able says it has seen no active exploitation and is building a hotfix — but watchTowr reported exploitation attempts against N-central honeypots **overnight**, which is the only timeline that matters when the PoCs are already public.

**Why it matters:** RMM platforms are the highest-leverage target in managed-services environments — one compromise fans out to every downstream customer. Same pattern as the cPanel/cPGuard and LNbits incidents in the last two weeks: disclosure-to-exploitation is now measured in hours.

### [📄 DeepMind's agents cut RSA-1024 forgery cost 3.5x and found a 1,600x better attack — under human supervision](https://www.securityweek.com/google-deepminds-ai-agents-make-1024-bit-rsa-keys-cheaper-to-attack/)
**⏱ Read time:** 3 min

Working with UC San Diego and Inria cryptographers, DeepMind agents found two results against legacy 1024-bit RSA. First, padding only protects signatures while the attacker controls less than roughly half the signed block — above that it "adds no protection at all," which bites PKCS#1 v1.5 as used by HSM PKCS#11 signing interfaces. The agents re-ran an earlier academic forgery and cut CPU time from 1,380 core-years to **391** (3.5x), designing, running and debugging the computation in under four days with ~20 human messages, mostly approvals. The key was not factored (that would be 500k–1M core-years).

Second, for many same-size keys the agents derived an algorithm making each additional key ~30x cheaper to factor (theoretical, unimplemented) — and for the harder low-control case, a method estimated ~1,600x better than the previous best. The signature attack needs ~4 billion pre-computed signing queries and doesn't recover the private key; hashing internally defeats it.

**Why it matters:** "Cryptographic hardness is a fixed assumption" is the thing that just stopped being true. 2048-bit+ is safe, but any HSM or firmware still signing PKCS#1 v1.5 at 1024 bits is now a documented, cheaper target — and the meta-point is that AI agents are doing publishable cryptanalysis in days.

### [📄 CISA adds GPUStack, FreeSWITCH, IBM Aspera and OpenSSH to KEV — three of four are 9.8](https://thehackernews.com/2026/11/cisa-warns-of-active-exploitation-of.html)
**⏱ Read time:** 2 min

CISA added four bugs to the Known Exploited Vulnerabilities catalog with active-exploitation evidence, FCEB remediation due **November 12**: IBM Aspera Faspex CVE-2026-123218 (9.8, auth bypass to privilege escalation), SignalWire FreeSWITCH CVE-2026-116779 (9.8, code injection → credential disclosure and command execution), OpenSSH "SSHole" CVE-2026-123158 (8.1, auth bypass on Linux), and **GPUStack CVE-2026-102895 (9.8, improper authentication → unauthenticated admin access, persistent admin API keys, worker/cloud-provider secret disclosure, and code execution via `POST /v2/inference-backends/from-yaml`)**.

The SSHole telemetry is the useful part: 22 exploitation attempts from 14 unique IPs since Nov 6, first honeypot hit Nov 7 12:46 UTC, six source IPs confirmed post-exploitation across 18 attack chains — cloud metadata queries, reading password hashes and root SSH keys, `authorized_keys` persistence, and in one case a Python C2 agent ("TAC Agent") attributed to an actor tracked as GT10.

**Why it matters:** GPUStack is AI infrastructure — an unauthenticated admin path into a model-serving control plane means model theft, backend repointing, and inference cost abuse. Add it to whatever you're scanning if you run self-hosted inference.

## 🔌 MCP / AI AGENTS

### [📄 ShadowBench-MCP: a task-preserving rephrase can make your router skip the safety tool](https://arxiv.org/abs/2611.11720)
**⏱ Read time:** 2 min
**📄 Related paper:** [papers/2026/11/shadowbench-mcp-shadow-invocations.md](../../papers/2026/11/shadowbench-mcp-shadow-invocations.md)

New benchmark (USENIX Security 2026) for **shadow invocation**: a request variant that keeps the task identical but makes an LLM router pick a riskier execution path — skipping validation, provenance, staging, redaction or audit. They separate task preservation (TPSS), operational pressure (OPSS) and route-geometric drift (RGAS) into a pre-execution SODS score. In a 120-decision ablation with a qwen3-32b router over six security-sensitive workflows, **efficiency-first routing produced a 29.2% shadow-invocation rate and 26.7% safety-tool skip rate**; policy-aware routing cut those to 4.2% and 1.7% — an 85.7% relative reduction. Pre-execution signals separated shadow routes at ROC AUC up to 0.94.

**Why it matters:** This is the first measurement of routing policy as a security boundary. If your agent picks tools by "cheapest/fastest," you have a measured 29% unauthorized-path rate before any attacker shows up.

### [📄 billion-context: context compression that keeps month-long agent sessions inside a 100K window](https://github.com/ranxianglei/billion-context)
**⏱ Read time:** 2 min

A TypeScript context-compression plugin (npm `billion-context`) that claims 5x fewer tokens and sessions spanning billions of tokens in a 100K window, supporting 20+ harnesses including Claude Code, Codex, OpenCode, Gemini CLI, Qwen Code, goose — and Hermes. It's trending hard today (+374 stars, 5,991 total, pushed today). The bundled paper reports a 4.5-month production study: 174,327 model calls, 18.76B cumulative input tokens, zero window violations on 204,800-token models, sessions of 8,584–12,049 calls, and a **95–97% prefix-cache hit rate with compression costing ≤2%**.

**Why it matters:** Long-lived agent sessions are where memory poisoning and stale-privilege bugs live. Compression that rewrites history is also a mutation surface — worth reading the paper for what gets dropped, not just the token savings.

### [StealthyPoison: Manipulating LLM Agent Behavior through Procedural Poisoning of Third-Party Skills](https://arxiv.org/abs/2611.12155)
**Authors:** Jingfen Qiao, Rui Li, Shuaiqun Pan, Olga Gadyatskaya, Andrew Yates, Evangelos Kanoulas (University of Amsterdam / Leiden) | **Published:** Nov 9, 2026

Corrupts a skill's *decision-critical rules* while keeping the advertised functionality intact, so the poisoned skill still "works" and produces no overtly malicious instruction to detect. ## 🔥 HOT TAKE + CONTENT IDEA

Write the post: **"Capability is the vulnerability — and this week we got the receipt."** Fable 5.2 posts 76.3% on a multi-stage cyber benchmark, DeepMind agents do publishable cryptanalysis in four days with 20 human approvals, and ShadowBench shows an agent router taking an unauthorized path 29.2% of the time purely because it was optimized for efficiency. Same thesis, three independent measurements: the risk isn't that the model gets jailbroken, it's that it's *good* and *cheap* and nobody re-checked the routing policy after the last optimization pass.

The concrete demo, 20 minutes of work: take one tool-routing agent with a "safety check" tool in its registry, run 30 tasks, then re-run the same 30 with purely cosmetic rephrasing ("quickly", "just", "minimal steps") and log how often the safety tool gets skipped. Publish the skip rate with the request pairs. ShadowBench gives you the metric names (TPSS/OPSS/RGAS) and the 29.2%→4.2% delta as your before/after — that's a post with a number, a method, and a fix.
