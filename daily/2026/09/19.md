### [📄 Bloomberg: overreliance on Palantir's Maven AI contributed to the Iran school strike that killed 123 children](https://www.bloomberg.com/graphics/2026-iran-school-attack/)
**⏱ Read time:** 5 min (graphics investigation)

A Bloomberg investigation published Sept 18 reports that Pentagon investigators found flawed intelligence, outdated imagery, and overreliance on Palantir's Maven Smart System — which uses Anthropic's Claude to semi-autonomously rank and prioritize targets — were among the factors behind the Feb 28 Tomahawk strike on the Shajareh Tayyebeh school in Minab, Iran, that killed 123 children. Palantir told Bloomberg there is no evidence its software was at fault and says it has since added "disqualifier flags" to Maven.

**Why it matters:** This is the clearest real-world case of a semi-autonomous AI ranking layer inside a lethal decision chain — the accountability, provenance, and human-in-the-loop questions your agent-security work frames abstractly now have a mass-casualty precedent.

### [📄 Public exploit code released for four Linux kernel flaws that grant local root](https://thehackernews.com/2026/09/public-exploits-released-for-four-linux.html)
**⏱ Read time:** 3 min

Researcher Asim Manizada published working exploits on Sept 18 for four kernel local-privilege-escalation flaws — DirtyAH6 (CVE-2026-80844), TUNderflow (CVE-2026-81000), PPPoEject (CVE-2026-68121), and DiagSpill (CVE-2026-74469) — after a coordinated hold so distros could ship fixes. **Why it matters:** Cheap, public local-root along the container/host boundary is the escalation primitive an attacker already inside a sandbox needs — patch everything running a pre-fix kernel today.

**⏱ Read time:** 3 min

## 🔌 MCP / AI AGENTS

### [📄 Closed-World Resolution Against Tool Hallucination in LLM Agents](https://arxiv.org/abs/2609.19425)
**⏱ Read time:** 4 min
**📄 Full breakdown:** [papers/2026/09/closed-world-resolution-tool-hallucination.md](../../papers/2026/09/closed-world-resolution-tool-hallucination.md)

The paper names a structural blind spot: agents call tools that don't exist and pass arguments no schema declares, and no tool-selection or gating defense can reject a call that was never a decision any gate made. It proves hallucination defense must sit *before* any causal gate, and measures 322 genuine hallucinations across ten models in which scale doesn't help (a 675B model matches a 7–8B one). Extending to MCP, merging several servers into one namespace creates collision and shadowing surfaces (M1–M5) that a single registry can't express — 154 hallucinations on the live MCP surface, including frontier models clean on the single-registry case.

**Why it matters:** Registry membership plus signature checks, placed ahead of the gate, is the concrete mitigation — and the MCP-merge taxonomy is directly testable against your own multi-server setups.

### [📄 Silence Is Endorsement: Verification-Status Laundering in LLM Agent Pipelines](https://arxiv.org/abs/2609.20211)
**⏱ Read time:** 4 min
**📄 Full breakdown:** [papers/2026/09/verification-status-laundering-llm-agent-pipelines.md](../../papers/2026/09/verification-status-laundering-llm-agent-pipelines.md)

Safety monitors often judge actions from summaries or stored handoffs rather than original evidence, so a handoff can preserve the claim "this action is authorized" while losing the fact that the claim was never verified. Removing the unverified provenance framing while holding the content fixed raises risky-action approval from 5%→60% on Llama-3.1-8B and 9%→98% on Qwen2.5-14B; a full proposer→summarizer→memory→monitor pipeline pushes approval to 57–81%. Telling monitors to "reject unverified authorization" is not a reliable cross-model fix.

**Why it matters:** If your audit trail is built on agent-written summaries, this is the failure mode that quietly launders an unverified action into an approved one — carry authorization provenance as structured state, not prose.

## 📄 PAPERS

### [The More It Says, the More You Pay: A Black-Box Audit of Provider-Side Token Inflation in LLM Services](https://arxiv.org/abs/2609.20370)
**Authors:** Leilei Chen, Lan Zhang, Chen Tang, et al. (8 authors) | **Submitted:** 17 Sep 2026

Defines the Provider-Side Token Inflation Attack (PTIA): a dishonest provider covertly lengthens generations to inflate pay-per-token bills while preserving task utility. Five attacks across the query, prompt, representation, and model layers push mean output length above 10.2x the clean baseline. The key insight is PTIA *saturation* — an initial attack sharply lowers the end-of-sequence probability, but further strengthening barely moves it — enabling a lightweight single-probe audit that needs no trusted reference model. It detects PTIA at 85.1% average with sub-2% false positives across four open-weight models and flags 7 of 15 real API services.

**Full breakdown:** [papers/2026/09/provider-side-token-inflation-audit.md](../../papers/2026/09/provider-side-token-inflation-audit.md)

## 🔥 HOT TAKE + CONTENT IDEA

The CrowdSec disclosure is the cleanest argument yet that **the real supply-chain surface isn't the malicious package — it's the offboarded employee's unrevoked OAuth token**. The token copied 170 private repos, left no trace in GitHub logs, and the company only learned of it months later from a forum dump. Ship a short piece today: *"Your ex-employees' GitHub tokens are the breach you haven't found yet"* — a five-step audit (revoke on last day, rotate every token on any package-registry compromise, trace OAuth token history via GitHub support, scope tokens to read-only where possible, alert on post-departure repo clones) tied directly to CVE-2026-45321. Pair it with a two-line nod to the Palantir/Claude story: the same provenance gap shows up in lethal targeting chains, which is why "who authorized this action" has to be structured data, not a model-written summary.
