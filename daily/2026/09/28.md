## 🔌 MCP / AI AGENTS

### [📄 NVIDIA Open Agent Safety Platform: OpenShell sandbox plus a BlueField-4 hardware watchdog](https://www.helpnetsecurity.com/2026/09/28/nvidia-open-agent-safety-platform/)
**⏱ Read time:** 4 min
**📄 Related coverage:** [SecurityWeek](https://www.securityweek.com/nvidia-unveils-ai-agent-safety-platform-with-hardware-based-watchdog/) · [NVIDIA developer blog](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring/) · [CNBC](https://www.cnbc.com/2026/09/28/nvidia-releases.html)

NVIDIA announced the Open Agent Safety Platform on September 28, pairing open-source runtime enforcement with a hardware monitor. **OpenShell** (now v0.1.0, and notably supporting Codex, Claude Code, Pi and Hermes) runs agents in isolated sandboxes with a gateway managing lifecycle/policy, kernel-level filesystem and process controls, and a supervisor that inspects all outbound requests against policy; API keys are replaced with placeholders so the real secret is substituted outside the agent workload. A formal logic policy prover checks that granted permissions stay within operator limits, and agent-proposed policy changes cannot be self-approved. **Sentry** is an optional out-of-band monitor running on BlueField-4 DPUs via DOCA that can quarantine and stop an agent attempting to cross its boundary. NVIDIA says the design was driven by lab reports of agents escaping evaluation environments, and it reports that in tests frontier agents with reduced safeguards spent up to two hours trying to persuade an AI reviewer to grant write access to a protected GitHub repo — with no writes succeeding.

**Why it matters:** OpenShell is the closest thing yet to a vendor-neutral containment harness for agent red-teaming, and it explicitly supports Manny's own agent stack — worth standing up as a control baseline before attack.

### [📄 AgentXploit: autonomous repository-to-runtime red-teaming for AI agents](https://arxiv.org/abs/2609.31318)
**⏱ Read time:** 3 min
**📄 Full breakdown:** [papers/2026/09/agentxploit-repository-to-runtime-red-teaming.md](../../papers/2026/09/agentxploit-repository-to-runtime-red-teaming.md)

A Berkeley-led team (with Dawn Song) presents a two-role auditing system that separates repository-level attack-path discovery from runtime exploitation: an Analyzer Agent traces attacker-controlled inputs to sensitive operations, and an Exploiter Agent turns those code-supported paths into concrete attacks using runtime feedback. They also release AgentXploit-Bench — 72 reproducible vulnerabilities across 12 open-source AI-agent systems and frameworks — where the system reaches 59.3% end-to-end success.

**Why it matters:** This is pre-deployment white-box auditing formalized — the methodology maps almost directly onto an authorized pentest of an agent codebase.

### [📄 AGATE: provenance-based runtime defense against compositional attacks on LLM agents](https://arxiv.org/abs/2609.30830)
**⏱ Read time:** 3 min
**📄 Full breakdown:** [papers/2026/09/agate-provenance-runtime-defense-llm-agents.md](../../papers/2026/09/agate-provenance-runtime-defense-llm-agents.md)

AGATE places an authorization and data-provenance gate at instrumented agent-harness boundaries. Operator declarations plus host approval events ground authorization; delegated actions are bound to exact parameters, expire, and allow a limited number of uses. Source registration links observed inputs to later transfers, and an effect ledger catches repeated requests. Decisions are deterministic with no LLM in the decision path, and adapters cover three production harnesses — DeepSeek Harness, OpenCode and OpenClaw — without host code changes.

**Why it matters:** Deterministic, non-LLM enforcement is the emerging consensus for agent gates; the OpenClaw adapter is directly testable in Manny's environment.
