## 🔐 SECURITY

### [📄 N-able N-central: 4th hotfix in 5 weeks for CVSS-10 pre-auth RCE — and N-able's own notice says it's exploited in the wild](https://thehackernews.com/2026/09/n-able-issues-fourth-n-central-hotfix.html)
**⏱ Read time:** 3 min

CVE-2026-86218 (CVSS 4.0: 10.0, CWE-96 static code injection) allows unauthenticated RCE on every on-prem N-central build below 2026.3.1.14 — the Hotfix 4 build shipped in the early hours of Sept 6, ~8 hours after Hotfix 3. N-able's status-page incident notice says the flaw "has been observed being exploited in the wild," while its release notes say there are "no confirmations" — and there are no IOCs or interim mitigations. Huntress is investigating a Sept 4 compromise of a fully patched production N-central server, and advises taking internet-reachable consoles offline.

**Why it matters:** This is the third distinct RCE class in the N-central line since Aug 2 — RMM servers are the perfect choke point for supply-chain attacks, and if Manny's clients run N-central, assume compromise until proven patched.

### [📄 Telerik UI padding-oracle chain weaponized: public exploit turns AES-CBC oracle into unauthenticated RCE](https://thehackernews.com/2026/09/telerik-ui-padding-oracle-bug-chained.html)
**⏱ Read time:** 3 min

TantoSec published a working chain against Telerik UI for ASP.NET AJAX: a padding oracle (CVE-2026-13182) plus an unguarded type-resolution flaw (CVE-2026-13181, CVSS 8.1) in RadAsyncUpload lets an unauthenticated attacker forge encrypted upload config and deserialize a mixed-mode DLL — web shell or memory-only payload. Progress patched in July (2026.2.708); exploitation needs a non-default encryption key (a recommended hardening setting) and takes ~127,000 oracle requests (~1 hour). No confirmed in-the-wild exploitation, though IONIX says it's tracking attempts.

**Why it matters:** A textbook case of "hardening setting becomes the pre-condition for a public RCE" — worth echoing in agent-tool config guidance, where the same dynamic plays out with MCP allowlists and tool permissions.

### [📄 JSCeal: compiled V8 JavaScript malware steals Google session cookies and OAuth tokens — and resists analysis](https://thehackernews.com/2026/09/jsceal-malware-can-bypass-google.html)
**⏱ Read time:** 2 min

Check Point unpacked JSCeal, a compiled-V8 (JSC) infostealer obfuscated with javascript-obfuscator (RC4 strings, control-flow flattening, proxy helpers). It enumerates installed browsers and queries saved secrets, cookies, and OAuth tokens — effectively bypassing Google auth — with a "router" function registering handlers for harvested data. CPR built a fully static deobfuscation pipeline to crack it; the malware family overlaps the WEEVILPROXY/MeadowLocust cluster and the SourTrade malvertising operation, which assembles malware entirely in the browser's memory.

**Why it matters:** Session-cookie and OAuth-token theft is the quiet killer behind "no password needed" breaches — the same credential class that agent identity tokens (MCP OAuth, Claude Code keys) now inherit.

### [📄 Rogue ScreenConnect clients spread a worm-like four-stage VBScript chain to newly connected hosts](https://thehackernews.com/2026/09/rogue-screenconnect-clients-spread-four.html)
**⏱ Read time:** 2 min

Huntress documented three incidents (Quick Assist tech-support scam, phishing MSI, fake Geek Squad refund lure) that install rogue ScreenConnect clients which then propagate a 1.vbs→4.vbs chain to every new Host that connects — worm-like behavior, with per-connection ID tracking to avoid re-hitting the same session. Payload branches include a ScreenConnect backdoor, UAC-bypass/persistence tooling, and a tunneling+XMRig miner that also disables Defender reporting and memory integrity. ConnectWise's interim advice: disable the TransferFiles permission; Huntress recommends reimaging.

**Why it matters:** Remote-access tooling is the infection vector AND the propagation medium — the same dual-use pattern applies to agent harnesses that can install or invoke RMM-style tooling on the hosts they touch.

## 📄 PAPERS

### [CONTINUITY: Security-Context Contracts for Composable LLM Agent Controls](https://arxiv.org/abs/2609.05269)
**Authors:** Chris Zheng, Geng Yang | **Published:** Sept 7, 2026 (announced)

Formalizes "security-context discontinuity" — individually-sound agent security controls (authz, provenance, policy) that silently drop or widen security context as actions cross component boundaries — and fixes it with assume-guarantee contracts plus signed root grants, provenance commitments, and effect-bound execution permits. A reference verifier survived 2,560 parameterized attack instances with zero harmful external effects.
