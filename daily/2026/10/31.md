## 🔐 SECURITY

### [📄 CISA adds two Ivanti Connect Secure flaws to KEV — the full chain is unauthenticated root](https://thehackernews.com/2026/10/attackers-chain-three-ivanti-connect.html)
**⏱ Read time:** 3 min

CVE-2026-111357 (CVSS 8.8, missing authentication for a critical function) and CVE-2026-118527 (4.3, predictable identifiers allowing attacker-controlled file upload) join CVE-2026-104935 (8.6, authentication bypass) already in KEV. Volexity attributed the chain to a new actor, UTA0576. Unlike typical edge-appliance intrusions, UTA0576 did not drop web shells — it pulled credentials and limited Active Directory metadata, ran host reconnaissance, and searched for administrator passwords and BitLocker recovery keys. Ivanti admits it shipped the auth-bypass fix first and was still developing the LPE fix when exploitation began. FCEB deadlines: November 2 and November 13.

**Why it matters:** Credential and recovery-key harvesting rather than persistence means the damage shows up weeks later in identity systems. This is the pattern to hunt for, not web shells.

### [📄 A shared ChatGPT link could run attacker code in your signed-in session](https://thehackernews.com/2026/10/a-shared-chatgpt-link-could-run.html)
**⏱ Read time:** 3 min

Parameter reported the flaw October 18; OpenAI fixed it in eight days and rated it P1. The chain: a shared chat contained HTML that renders as a web page via Preview, plus an interactive graph that loads MathLive into the main page. MathLive left a listener accepting on-screen-keyboard messages from any sender, and those messages could carry raw HTML. The sandboxed Preview frame therefore reached into the trusted page, built a frame the browser treated as chatgpt.com, and loaded a script from YouTube — permitted by the content security policy, which blocked inline code but allowed that origin. The code then called ChatGPT's own signed-in APIs, enumerated recent conversations, opened a never-shared private chat and exfiltrated part of it. By October 26 both frontend versions rejected the messages.

**Why it matters:** Three reasonable design choices, each defensible alone, composed into full account takeover. The CSP origin allowlist did the final work — the same mistake is sitting in most agent web UIs that embed third-party renderers.

### [📄 TeamViewer flaw lets the controlled machine attack the person controlling it](https://thehackernews.com/2026/10/teamviewer-flaw-lets-remote-computers.html)
**⏱ Read time:** 2 min

CVSS 8.8. The host tells the viewer how large its screen image is; the viewer sizes a buffer from that number, the calculation overflows and under-allocates, and subsequent screen data writes past the end. Minimum impact is a remotely re-triggerable crash of the viewer's client. On Windows, researcher Omri Dar at Remedio bypassed the OS exploit mitigations and ran code of his choosing in the viewer, though with a stand-in supplying part of the attack data rather than purely over the network. Fixed in 15.83 across Full Client on Windows, Linux and macOS, the Portable edition, and the Android Remote Control app.

**Why it matters:** The trust direction in remote support is backwards from how everyone models it — the party you connect to is the attacker. High-value for any red team that can plant or compromise a jump host.

### [📄 WordPress Core RCE draws ~63,000 attack attempts in 24 hours](https://thehackernews.com/2026/10/wordpress-rce-flaw-draws-nearly-63000.html)
**⏱ Read time:** 2 min

An unpatched-then-patched remote code execution flaw with no CVE identifier, CVSS 8.1, affecting WordPress Core 4.7 through 7.1.3. Full-package core upgrades unpack into a predictable, web-accessible staging path under `wp-content/upgrade`, and that copy includes the installer. An unauthenticated attacker who requests the installer at the right moment during the unpack window can drive it to PHP execution. Wordfence requires a full-package update containing installer files, public web and PHP access to the staging tree, and a predictable or discovered staging path.

**Why it matters:** Race conditions on upgrade windows are the classic blind spot in "we patched within a day" claims. Mass scanning at this rate means the window, not the patch, is the exposure.

### [📄 Agent skills are an unaudited supply chain: 88,000 of 1.53M skills carry an oversight-loosening directive](https://arxiv.org/abs/2610.37734)
**⏱ Read time:** 3 min
**📄 Related paper:** [papers/2026/10/when-skills-tell-agents-not-to-ask.md](../../../papers/2026/10/when-skills-tell-agents-not-to-ask.md)

The first large-scale measurement of SKILL.md packages finds about one in seventeen contains an instruction telling the agent to skip approval, bypass checks with `--no-verify`, or keep working without checking in — and 70.1% of those apply unconditionally rather than only in CI. Skills that run shell code, install packages or use sudo have 1.7–1.8x the odds, and do not compensate with more tightening language. Existing open-source skill scanners catch at most 46% of them at precision below 0.4.

**Why it matters:** This is the single most actionable number for anyone auditing an agent harness today. The directive is in the instruction layer, invisible to static dependency scanning.

### [📄 Poisoned Skills: a jailbreak in a Markdown skill file lifts attack success from 0.5% to 45%](https://arxiv.org/abs/2610.37738)
**⏱ Read time:** 2 min
**📄 Related paper:** [papers/2026/10/poisoned-skills-jailbreak-markdown.md](../../../papers/2026/10/poisoned-skills-jailbreak-markdown.md)

A LangChain agent whose system prompt is assembled from a user-provided Markdown file, tested across seven open-weight models on 270 forbidden questions in nine harm categories. Benign baseline: 0.5% mean ASR. With a jailbreak embedded in the skill file, combining persona manipulation and a GPTFUZZER payload: 45% mean, 68.9% peak. Obfuscation did not help — zero-width-character and phonetic variants both underperformed plain text, with the phonetic variant dropping to 30%. Companion work, [Scan Before You Install](https://arxiv.org/abs/2610.37901), ships a six-module scanner hitting 95.9% recall at 4.22% FPR and confirmed 53 of 59 findings across 23 of the 75 most-starred GitHub skill repos.

**Why it matters:** Configuration is an injection channel. Anything that lets a user or a marketplace supply the agent's instructions is also supplying its attack surface, and obfuscation tricks are wasted effort compared to just fixing the trust boundary.

## 🔥 HOT TAKE + CONTENT IDEA

Three independent Friday papers converged on the same finding: the agent skill file is the attack surface, and the scanners everyone installed this quarter catch less than half of it. The number worth building content around is **88,000** — skills that tell the agent not to ask permission, sitting in public repos, loaded silently at init.

Concrete idea: write and ship a `skill-audit` script that walks a `.claude/skills` tree, flags `--no-verify`, `--force`, `sudo`, `curl | sh`, and unconditional "proceed without approval" phrasings, and scores each skill. Post the scan of the top 75 starred skill repos as the launch artifact — 53 of 59 confirmed findings exist in that set, so the results are real before you write a word of commentary. Title angle: "One in seventeen skills tells your agent to stop asking." Demo the detector gap directly: run Cisco's Skill Scanner and NVIDIA's SkillSpector side by side with your own on the same corpus and publish the delta.
