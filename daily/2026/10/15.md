## 🔐 SECURITY

### [📄 Ivanti Connect Secure: three chained zero-days (CVE-2026-104935) grant unauthenticated root on patched appliances](https://www.volexity.com/blog/2026/10/13/a-series-of-unauthenticated-events-chained-exploitation-of-ivanti-connect-secure-zero-days/)
**⏱ Read time:** 3 min

Volexity found an unknown actor, UTA0576, using a three-part zero-day chain against a *fully patched* Ivanti Connect Secure appliance (22.8R2.4). An authentication bypass + RCE (both CVE-2026-104935, fixed Oct 13) were chained with a separate privilege-escalation flaw (still unpatched) to reach root. The chain patches library code in memory only and restores it afterward, so Ivanti's own Integrity Checker Tool detects nothing; the actor stole LDAP/AD credentials, LAPS passwords and BitLocker keys, and deleted its own audit-log traces. CISA added it to KEV on Oct 13.

**Why it matters:** The definitive lesson of the week — file/integrity-based defense failed, only memory forensics worked. The same "containment + behavioral monitoring over static detection" argument applies directly to agent and MCP sandboxing.

### [📄 Cisco warns of active attacks on a new critical Secure Email Gateway flaw (CVE-2026-76519, CVSS 9.8)](https://thehackernews.com/2026/10/cisco-warns-of-active-attacks.html)
**⏱ Read time:** 2 min

Cisco disclosed CVE-2026-76519: an unauthenticated sender can write files to the appliance OS via a crafted email attachment and, if successful, run commands as root. Only gateways with File Reputation enabled and Content Scanner Tools older than 25.3.0.5525 are affected; Cisco found it via its own internal scanning and confirmed in-the-wild attacks in October. Fix exists (AsyncOS 15.5.5-014 / 16.5.0-780, or the standalone scanner update); no workaround.

**Why it matters:** Email security gateways are a prime, internet-exposed pivot into root — and Cisco says exploitation is already happening, so this is a patch-now item.

## 🔌 MCP / AI AGENTS

### [📄 VerCellBreak: AIR bypasses Vercel Sandbox's domain allowlist to exfiltrate agent secrets](https://www.air.security/blog-posts/vercel-break)
**⏱ Read time:** 3 min

AI-security startup AIR found that Vercel Sandbox's Server Name Indication (SNI) filtering can be bypassed by abusing the interaction between mutual TLS (mTLS) and the AIA certificate extension. A rogue agent can therefore reach an attacker-controlled server that is *not* on the domain allowlist and leak keys/tokens — with no detection signal at the sandbox boundary. Vercel acknowledged the issue; at disclosure no patch existed.

**Why it matters:** The strongest agent-sandbox network control (SNI allowlisting) is defeatable — treat "my agent is sandboxed" as a containment problem, not a solved one, and monitor egress behavior, not just allowlist membership.

### [📄 ToFu: 253 verified bugs across 118 MCP servers — and a "Repeat-After-Me" prompt that hijacks six agent frameworks](https://arxiv.org/abs/2610.13651)
**⏱ Read time:** 3 min
**📄 Related paper:** [papers/2026/10/tofu-llm-orchestrator-tool-trust-boundary.md](../../papers/2026/10/tofu-llm-orchestrator-tool-trust-boundary.md)

A 33-page preprint introduces ToFu, a tool-aware fuzzing framework that derives semantic security checks from MCP tool metadata and a CWE-guided sanitizer corpus. Evaluating 273 open-source MCP servers (3,405 tools), the authors verified 253 semantic security bugs across 343 tools in 118 servers (path traversal, SSRF, command injection, data exfiltration, log injection). The companion "Repeat-After-Me" technique — prompting a model to echo a structured tool call — triggered attacker-directed tool execution in six frameworks (LangGraph, AutoGen, Google ADK 2.0, AWS Strands, Microsoft Agent Framework, CrewAI).

**Why it matters:** It crystallizes the core agent-security bug: model-controlled arguments are treated as trusted by tools they were never designed to constrain — exactly the trust boundary Manny red-teams.

## 🔥 HOT TAKE + CONTENT IDEA

Both are *static boundary* defenses that assume "if it looks right, it is right."
