### [📄 Anthropic opens Claude Duet: a proactive agent app that messages you first](https://claude.com/resources/articles/claude-duet)
**⏱ Read time:** 3 min

Anthropic opened a US waitlist research preview of Claude Duet for Pro and Max plans — a standalone iOS, Android and web app built around Claude Opus 5.5 where the agent runs in the background on its own VM with its own browser, checks connected accounts every few hours, and sends a morning brief plus ad-hoc alerts. It carries over memory, skills and connected apps from the main Claude account, and can drive the 6,000+ connectors in the Claude Marketplace (Gmail, Slack, QuickBooks, Stripe, Gusto, HubSpot, Docusign, Shopify), paying via Stripe Link virtual cards or Shop Pay.

The safety design is the interesting part: credentials follow the Claude Managed Agents model so Duet never sees passwords or sign-in tokens; a dedicated classifier and safety system prompt block the strictest tier (card numbers, government IDs) and gate health/finance data behind explicit instruction; actions pass through the auto-mode classifier; and sends, payments, signatures and deletes require per-action approval, with securities trading and inter-account transfers off-limits even with approval. Red team plus an external pen test plus bug bounty coverage.

**Why it matters:** This is the reference implementation of an agent with real credentials, real money movement and an approval gate — read the threat model, because your customers will be compared against it.

### [📄 Recursive ships Flint: a 40B laptop coding model that its own AI research system mostly built](https://techcrunch.com/2026/10/21/recursive-launches-flint-a-laptop-coding-model-it-says-was-largely-built-by-ai/)
**⏱ Read time:** 2 min

Recursive released Flint, a free Apache 2.0 coding model under 4 GB-class footprint — 40B parameters with 2.5B active per token (MoE) — that runs offline on a laptop and was built in under four months with its "Eureka Machine" automated research system contributing to pretraining, post-training and inference. Eureka's concrete contributions: a sparser model shape, low-bit training that cut size 71% with near-zero quality loss, and custom kernels. Recursive claims ~131 tok/s on an M4 Pro versus 58–69 for Gemma 4 and Nemotron 3.5 Lightning, and best-in-class under 50B on SWE-Bench Verified, with only Qwen3.8 27B ahead on its own six-benchmark average.

**Why it matters:** A local, offline coding model with no per-token billing changes the exfil economics for agent harnesses — and it is the first public artifact from a $4.65B-valued recursive-self-improvement bet.

### [📄 GitLab patches CVE-2026-110264: CVSS 10.0 unauthenticated RCE reaching back to 7.0 (2014)](https://thehackernews.com/2026/10/critical-gitlab-flaw-cvss-100-could.html)
**⏱ Read time:** 3 min

GitLab's October 21 release fixes an integer overflow in the Onigmo regex compiler that, under undisclosed conditions, lets an unauthenticated user run arbitrary code on a self-managed server. Because GitLab ships and patches Onigmo inside its own packages, the flaw is present in every release since 7.0 — and the October 12 fix (CVE-2026-97229) only covered 19.2+, so instances patched nine days ago are back in range. GitLab backported to 18.11.13, 19.0.10, 19.1.9 and 19.2.9, outside its normal three-release policy, and published two Sigma detections ("Onigmo native worker crash", "Org mode render error burst"). It is the fourth regex-engine RCE the same researcher (joaxcar) has reported in a month.

**Why it matters:** No workaround, no preconditions published, upgrade causes DB-migration downtime on single-node — this is a same-week patch for any self-managed GitLab in scope.

### [📄 Microsoft: Storm-0940 ran ARTEX, an agentic AI pentest framework, at 2,900 sign-ins per minute](https://thehackernews.com/2026/10/china-linked-hackers-use-artex-ai.html)
**⏱ Read time:** 3 min

Microsoft attributed the ConnectWise Cloud Backup supply chain compromise to China state-aligned Storm-0940, which used ARTEX — a Go-based agentic AI penetration-testing framework that went closed-source after abuse against South Korean financial firms — to automate recon, password spraying and OAuth application abuse. Between October 10 and 14 the actor's infrastructure pushed 151,000+ failed logons across 327 accounts in eight organisations, peaking at 2,900 failures per minute and 111,000 in a single day. On October 15 the agents obtained identities of multiple ConnectWise cloud applications and authenticated downstream through pre-existing app trust; in some cases they reached Graph and directory operations, modifying app credentials for persistence in under three hours from initial targeting.

**Why it matters:** This is the first well-documented case of an agentic framework scaling a supply-chain intrusion end-to-end — and the persistence mechanism (app credential modification that survives remediation of the original app) is a detection gap most IR playbooks miss.

### [📄 Node.js fixes an out-of-bounds write in its bundled Brotli decoder, plus nine more flaws](https://thehackernews.com/2026/10/nodejs-brotli-decoder-bug-could-allow.html)
**⏱ Read time:** 2 min

Node.js shipped 22.23.4, 24.22.1 and 26.12.1 on October 21, fixing 10 flaws. The headline is a heap out-of-bounds write in the bundled Brotli decoder reachable through `node:zlib` or any `fetch()` response with Brotli encoding — i.e. attacker-controlled input in a request body or upstream response. Node describes it as remote code execution; the public PoC from October 22 only achieved code execution against a deliberately weakened build, and crashed a standard one with a limited memory read. Also patched: two TLS certificate-validation bypasses via odd IP address forms (CVE-2026-106069, CVE-2026-105483), a null-byte truncation in `dns.resolve` (CVE-2026-105482), and `crypto.randomUUID()`/`randomInt()` returning identical values across processes in single-executable/startup-snapshot builds (CVE-2026-106074). Node 20.x and earlier get nothing.

**Why it matters:** Every MCP server, agent gateway and harness in Node is in scope, and the seed-determinism bug is a quiet killer for anything generating agent session tokens or nonces.

### [📄 OpenCode: a malicious MCP server gets code execution at sign-in on Windows and WSL — and there is no CVE](https://thehackernews.com/2026/10/opencode-flaw-lets-malicious-mcp.html)
**⏱ Read time:** 3 min

Pillar Security found that when a developer runs `opencode mcp auth`, the MCP server supplies the OAuth authorization endpoint, which OpenCode passed to the `open` browser helper — which on Windows built a PowerShell command around the URL without escaping. An HTTPS URL crafted to carry a PowerShell command executes with the developer's privileges. Fixed in 1.18.33 on September 28 as an unlabelled "refactor" of browser-launch code, with no CVE and no advisory, so 1.0.137 through 1.18.32 stay invisible to scanners. Anomaly's position: user-configured MCP servers are "outside our trust boundary." Pillar rated it 9.8. macOS and Linux are unaffected; an HTTP/HTTPS prefix check does not help. This is distinct from the OpenCode Console API-key exposure reported separately.

**Why it matters:** The same bug class as CVE-2025-6514 in `mcp-remote` — and the vendor's threat-model exclusion means your SBOM will never tell you.

### [📄 LiteLLM 1.107.0 backdoored — because Claude Code printed GitHub CLI OAuth tokens into responses](https://thehackernews.com/2026/10/litellm-suspects-github-token-leak-in.html)
**⏱ Read time:** 3 min

LiteLLM's release pipeline was abused on October 21 to publish 1.107.0 (PyPI, Docker Hub, GHCR including `latest`) with a credential stealer plus an hourly beaconing RAT — unusually, using both a `cook.pth` interpreter hook and `sitecustomize.py` simultaneously, the first in-the-wild combination Wiz has documented. The root cause is the standout finding: LiteLLM says it observed "specific situations in which Claude Code will embed a user's GitHub CLI OAuth token into a response body," which then landed in LiteLLM's own request/response logs. Three engineers' GitHub CLI credentials were used — one account to trigger the project-releaser run, another to approve it. Wiz saw stolen AWS role credentials validated with `sts:GetCallerIdentity` then `bedrock:ListFoundationModels` about 4.5 hours later: LLMjacking.

**Why it matters:** An AI gateway logging LLM traffic is now a credential sink, and the leak came from the coding agent's own output framing — sanitize response bodies before they hit any log.

## 📄 PAPERS

### [Compaction Laundering: Provenance Destruction in Context-Compacting Coding Agents](https://arxiv.org/abs/2610.29869)
**Authors:** Arshan Dabirsiaghi (Pixee) | **Published:** Oct 21, 2026

Context compaction in coding agents is a trust boundary: harnesses that flatten typed messages into one string with `[User]:` labels destroy provenance, so an attacker who controls anything the agent reads can forge a user turn that survives summarisation as a real instruction — 87–100% success across pi, OpenCode, Cline, Aider and OpenHands, versus 0% in role-typed harnesses (Codex, Gemini CLI, Qwen Code, Continue).

## 🔥 HOT TAKE + CONTENT IDEA

Two stories today combine into one concrete audit you can run in an hour. First: `grep` your agent harness for where the message list is serialised — if it becomes one string with `[User]:` / `[Assistant]:` labels before summarisation or before hitting a model, you are exposed to compaction laundering at 87–100% success (paper 1), and no system prompt fixes it, because the provenance is gone before the model reads it. Second: `grep` your gateway logs for `gho_` and `ghu_` prefixes — LiteLLM got backdoored because Claude Code emitted a GitHub CLI OAuth token in a response body that then got logged, and three engineers' accounts were enough to ship a RAT to `latest`. Both are serialiser-and-logger bugs, not model bugs, which is why they are fixable today.

Content idea: "Your agent's memory is a privilege-escalation path" — walk through three papers (compaction laundering, memory injection, correlated approval failures) as one attack chain: forge a turn → persist it as memory → survive the approval gate → land `curl | sh`. Pair it with the OpenCode no-CVE case to make the point that the harness, not the model, is the security boundary.
