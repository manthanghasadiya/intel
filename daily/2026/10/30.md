## 🔐 SECURITY

### [📄 Official Claude Code extension on the Cursor Marketplace trojanized with a persistent SSH backdoor](https://thehackernews.com/2026/10/official-claude-code-vs-code-extension.html)
**⏱ Read time:** 4 min

A modified `anthropic.claude-code` 2.1.313 was served through Cursor's marketplace between 02:27 and 13:35 PT on Oct 29, hitting at most 5,000 users before Cursor pulled the listing. A 66-line loader prepended to the legitimate JS bundle adds an attacker key labeled `svc-telemetry` to `~/.ssh/authorized_keys`, opens a reverse tunnel to `134.209.82[.]225`, plants persistence via scheduled task / crontab / LaunchAgent, and beacons host recon to `:8099` over plain HTTP — public IP via api.ipify.org, hostname, username, OS/arch, cwd, git global email, and the *names* of up to 40 env vars matching KEY/TOKEN/SECRET/PASS/AWS/GCP. Fixed in 2.1.314.

**Why it matters:** The compromised artifact was the officially branded agent itself, delivered by auto-update. Any Claude Code instance with auto-update on was in scope. This lands nine days after OVHcloud's CLI binaries were replaced through a hijacked contributor account from the GlassWorm operation — the agent toolchain is now the preferred initial-access path.

### [📄 Binance loses ~$6B: attackers made Binance's own hot wallet sign 50 pre-staged authorizations](https://thehackernews.com/2026/10/binance-suffers-security-breach.html)
**⏱ Read time:** 5 min

Binance disclosed a "security incident" affecting ~$6.3B in assets, with ~$2.97B frozen on-chain; Chainalysis puts the theft at ~$5.912B, roughly 4x the next-largest crypto heist, and Elliptic at $6.43B. Binance's initial finding is a compromised DevOps engineer's laptop that yielded access to a service container and the ability to submit unauthorized withdrawals — no private key leak. At 20:20 UTC the operator submitted one transaction containing 50 authorizations, each signed by the Binance hot wallet and each pointing at a sweeper contract that only accepts the operator's instructions; by pre-signing 50 consecutive nonces the attacker guaranteed one would still be valid when it executed. 3m24s later a single transaction moved 167,464 ETH and 63 tokens, including 1.615B USDT.

**Why it matters:** This is the Bybit playbook again — don't steal keys, make the victim's signing infrastructure sign. TRM Labs and Chainalysis attribute it to DPRK's TraderTraitor with high confidence, with staging underway at least 36 hours ahead. If your threat model still treats "no key exfil" as containment, it's wrong.

### [📄 Linux kernel TCP use-after-free (CVE-2026-98432, kernel team: 9.8) — Ubuntu and RHEL still unfixed, and an Anthropic model wrote the exploit](https://thehackernews.com/2026/10/linux-kernel-tcp-flaw-with-98-cvss.html)
**⏱ Read time:** 4 min

A race in IPv4 TCP connection setup: the kernel hands the IP options from a pending request to the new socket without copying them, so a socket destroyed while another CPU is still reading those options yields a use-after-free. IPv6 is unaffected. The bug dates to Linux 4.4; upstream fix landed Oct 5, credited to Anthropic researcher Xinyang Ge. Anthropic said on Oct 27 that its model wrote an exploit turning the flaw into unauthenticated remote root against servers with a multipath TCP listener — and Go 1.24+ requests MPTCP by default on listening sockets, per the Go security team on Oct 29.

**Why it matters:** Score dispute is the story. Kernel CVE team says 9.8 (low complexity, attacker-induced race); Red Hat says 5.9 moderate, no demonstrated confidentiality impact; Ubuntu and RHEL have shipped nothing as of Oct 29, while Debian, Oracle, SUSE and Amazon have. Model-authored kernel LPE against unpatched LTS is the new baseline.

## 🔌 MCP / AI AGENTS

### [📄 Cisco open-sources Quarry: a neurosymbolic rule language for agent attacks split across benign steps](https://www.securityweek.com/cisco-open-sources-quarry-to-catch-ai-agent-attacks-hidden-in-harmless-steps/)
**⏱ Read time:** 3 min

Project Quarry combines ML classifier and LLM-judge evidence with symbolic checks — exact conditions, sequences, string matches, tool relationships — to catch intent that only exists across a series of individually permitted actions. It covers single- and multi-turn LLM conversations, agents, tool use, **MCP interactions**, and multimodal input, and is positioned as the policy/evaluation layer of Cisco's Integrated AI Security & Safety Framework. A plugin lets a coding agent compose, compile and test rules from a plain-English risk description.

**Why it matters:** This is the detection model agent security has been missing — per-action allowlists can't see a kill chain assembled from 40 legitimate tool calls. It's also a working template for writing your own detections against MCP traffic. Motivation is concrete: the 2025 Claude Code campaigns against ~30 organizations and Mexican government systems were decomposed into routine-looking tasks that read as an authorized pentest until the sequence completed.

### [📄 claude-mem is the #1 trending repo: persistent cross-session memory for every agent, uploaded to a hosted observer by default](https://github.com/thedotmack/claude-mem)
**⏱ Read time:** 2 min

claude-mem captures tool-usage observations during a session, compresses them into semantic summaries, and injects the relevant ones into future sessions — across Claude Code, Codex, Gemini, Copilot, OpenCode and Hermes. The default install path signs you into a hosted memory backend ("CMEM Pro") on a 30-day trial; a local observer is opt-in via `--provider host`. Its Grok Bot awareness pilot appends dated lines tagged `decision`, `bugfix`, `security_alert` and `sensitive` into a monthly memory log that the bot re-reads from disk.

**Why it matters:** Persistent agent memory is a durable, cross-session write primitive. Anything that survives compaction and gets re-injected is a persistence channel for injected instructions — and a summary store that classifies `security_alert` and `sensitive` observations is, by construction, a concentrated index of exactly what you'd want to exfiltrate.

**Authors:** Jie Fu, Shuang Wu, Ashish Kundu, Wendy Hui Wang, Yuan Hong | **Published:** Oct 28, 2026

A peer-controlled development component — backend service, test harness, CI job — should have diagnostic authority over its own state but no action authority over the victim's files, shell or credentials. ## 🔥 HOT TAKE + CONTENT IDEA

Two items today describe the same shift from opposite ends: a trojanized official Claude Code extension that installed a reverse SSH tunnel, and the #1 trending repo being a service that captures every agent session and ships compressed summaries to a hosted backend. The agent toolchain is now a credential-access path *and* a persistence layer, and neither is covered by the "is the model aligned" conversation.

Concrete move: write the paired piece — **"Your agent's memory is an exfil channel, and its extension is the implant."** Take claude-mem's observation schema (`security_alert`, `sensitive`), show what a poisoned summary looks like when it re-injects into session 4, then write three Quarry-style rules that catch (a) SSH key appended to `authorized_keys` during an agent session, (b) outbound connections to a non-allowlisted host from the agent's process tree, (c) a memory write tagged `sensitive` later read by a different principal. That's a demo-able detection pack, not a thinkpiece — and Quarry is open source, so the rules can actually be committed.
