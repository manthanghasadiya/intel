## 🔐 SECURITY

### [📄 Telegram Android flaw runs attacker code when you answer a voice call — no CVE, patched silently in September](https://thehackernews.com/2026/10/telegram-android-flaw-lets-attackers.html)
**⏱ Read time:** 4 min

NebuSec disclosed a memory-safety flaw in Telegram for Android's handling of `MediaState` call-setup messages: the parser validated the camera-rotation field, then read the video-state field even when absent, reading out of bounds. An attacker with an ordinary account calls the victim; roughly 30 seconds after the call is answered, code runs. Affects every build from 8.6.2 (March 2022) through 12.10.3. Fixed in 12.10.4, released late September. Confirmed on ARM64 devices; no evidence for iOS or desktop, though the shared `tgcalls` library got the same "Fix camera rotation" correction in April 2026.

**Why it matters:** This is a zero-click-after-answer RCE in an app with ~1B installs and no CVE, disclosed three weeks after the patch. It's the strongest argument yet for treating messenger call parsers as hostile-input boundaries — and for the fact that silent vendor patches mean your exposure window is invisible unless you track upstream commits.

### [📄 26,400 still-valid cloud and AI credentials found in public Gitee repositories](https://thehackernews.com/2026/10/26400-valid-cloud-and-ai-credentials.html)
**⏱ Read time:** 3 min

Independent researcher Ben Zimmermann scanned 7.25M public Gitee repos with TruffleHog and Kingfisher, live-validating every hit. 26,400 credentials still worked. Top: 9,473 Alibaba Cloud AccessKey pairs, then 3,805 YouTube API keys, 3,170 DeepSeek keys, 1,489 Zhipu BigModel keys, 1,348 OpenAI keys, plus GitHub, AWS, GCP and Gemini. One was described as "an active organization-admin credential for a major enterprise AI platform." Full commit history was scanned, so keys later deleted from code still counted.

**Why it matters:** Chinese AI-lab API keys are now a first-class credential class in the wild, and most of these were never revoked. For red-team work, this is a ready-made list of live inference quota, billing, and possibly fine-tuning access — and for defenders, an argument that key rotation, not history rewriting, is the only remediation.

### [📄 PHP2Shell now exploited against internet-facing Palo Alto management interfaces; root chain added to KEV](https://thehackernews.com/2026/10/attackers-exploit-php2shell-flaws-in.html)
**⏱ Read time:** 3 min

Palo Alto Networks confirmed active exploitation of CVE-2026-109618 / CVE-2026-109619 (CVSS 9.2, unauthenticated RCE in PHP) against the PAN-OS management web UI and XML API. No special configuration is needed — exposure is simply "management interface reachable from the internet." CISA added the Linux kernel LPE used in the chain, Fragnesia (CVE-2026-46300, 7.8), to KEV with an October 31 deadline, noting the three flaws chain into PHP web shells running as root. **Why it matters:** PHP2Shell went from disclosure leak to rooted government-adjacent infrastructure in eight days. The lesson is the chain, not the bug: unauth RCE in a web tier plus a local LPE is now a packaged, AI-assisted intrusion kit.

### [📄 Warp Panda used a CVSS 2.7 VMware ESX logging flaw as a zero-day to erase its audit trail](https://thehackernews.com/2026/10/china-linked-hackers-exploited-vmware.html)
**⏱ Read time:** 3 min

CISA added CVE-2026-41709 to KEV after CrowdStrike's Legal Threat Landscape Report tied it to Warp Panda (aka Armory Castle, Clay Typhoon, UNC5221) targeting the U.S. legal sector. The flaw is an insufficient-logging issue in VMware ESX — CVSS 2.7 — letting an admin-privileged actor perform operations without generating logs. CrowdStrike says the group exploited it as a zero-day in early 2026, then pivoted into vCenter to deploy BRICKSTORM and SharpStorm, harvested cloud session tokens, and registered rogue MFA devices.

**Why it matters:** A 2.7 severity score got a KEV entry because of what it enables, not what it scores. Any scoring pipeline that sorts by CVSS alone buries this — and audit-log suppression is precisely the step that makes everything downstream invisible.

## 🔌 MCP / AI AGENTS

### [📄 GitHub ships an install-time package firewall, explicitly aimed at agents and CI runners auto-installing dependencies](https://thehackernews.com/2026/10/github-launches-npm-firewall-to-block.html)
**⏱ Read time:** 2 min

GitHub's new npm package firewall sits between endpoints or internal registries and upstream registries, inspecting metadata requests and downloads as a policy gate before install. Public preview for GitHub Enterprise Cloud. Policies include blocking packages with active malware advisories, blocking by vulnerability severity (default: critical only), blocking attestation downgrades, blocking newly-introduced `preinstall`/`postinstall` scripts, and a 1–365 day version cooldown defaulting to 1 day.

**Why it matters:** GitHub names the threat model directly — "AI agents and CI runners automatically install dependencies... without their explicit permission." This is the first mainstream control that treats agent-driven dependency resolution as an untrusted, policy-gated action rather than a build step.

### [📄 CopilotKit/OpenBot: AI coworkers that each get their own computer, with every action decided before it happens](https://github.com/CopilotKit/OpenBot)
**⏱ Read time:** 3 min

OpenBot is an open-source, self-hosted ChatGPT/Claude-shaped workspace where each agent gets its own browser with its own logins, its own files, and only the granted tools. The stated design property is pre-execution decision plus post-execution recording — actions are adjudicated before they run, then audited. Any AG-UI agent can be attached as a coworker. It is explicitly a template, not a product: clone it, replace the example tenant package, run it. Beta, under active development, with `OPENBOT_SINGLE_USER=true` admitting every request as administrator until sign-in is enabled.

**Why it matters:** Per-agent VM isolation plus pre-execution authorization is the architecture the last month of agent-breach reporting has been pointing at — Warp, CyberStrikeAI, OpenAI's sandbox escapes. The single-user default is also a live footgun if anyone deploys the example config to a reachable host.

### [📄 Related paper: Log-To-Leak — MCP tool descriptions used to induce a post-hoc exfiltration call](https://arxiv.org/abs/2610.36108)
**⏱ Read time:** 2 min
**📄 Related paper:** [papers/2026/10/log-to-leak-mcp-post-hoc-logging.md](../../../papers/2026/10/log-to-leak-mcp-post-hoc-logging.md)

Log-To-Leak is an additive attack that doesn't hijack the legitimate tool call at all — it appends a second, attacker-controlled call after the final legitimate one, targeting the user query, MCP server name, server response and agent response. Across 18 model-server pairs it hits 62.64–100% ASR with legitimate task completion essentially unchanged (≤6.63pp delta), and three tested defenses leave residual ASR above 55%.

**Why it matters:** If successful task completion and unauthorized post-hoc disclosure coexist, no output-quality metric will catch this. Host-controlled authorization for *secondary* tool calls is the missing control.

## 🔥 HOT TAKE + CONTENT IDEA

**The Telegram bug is your content for today, and the angle nobody will take is the disclosure economics.**

NebuSec found an out-of-bounds read in a `MediaState` parser, Telegram fixed it in 12.10.4 in late September, and it was disclosed on October 29 with no CVE, no advisory, and no user notification — a 5-week silent window where every Android user on 8.6.2 through 12.10.3 was reachable by anyone with a phone number. Compare that to PHP2Shell, which got an emergency out-of-cycle release and a CISA KEV entry inside a week because it was a server-side bug with a brand name.

The take: **client-side RCE in consumer messengers gets a version bump; server-side RCE in enterprise appliances gets a national security response.** Same CVSS, wildly different treatment — because messenger vendors have no reporting obligation and no customer who can escalate.

Content idea: a short teardown titled *"Telegram patched a call-answer RCE in silence and nobody noticed for five weeks."* Walk the `MediaState` field-mismatch bug from the public 12.10.3 source, show why "check rotation, read video state" produces an OOB read, then make the structural point — audit your messenger *and* your appliance versions, because the vendor's disclosure behavior is part of your threat model. Pair it with the Diff-check workflow: watch upstream commit messages like "Fix camera rotation" as an early-warning channel, since that commit landed in April 2026 across tgcalls and only reached Android in September.
